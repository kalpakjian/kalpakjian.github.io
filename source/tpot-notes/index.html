1. 什麼是 TPOT？

讓電腦自動幫你建構機器學習模型——TPOT 是 AutoML（自動化機器學習）領域裡最有名的開源工具之一：你負責準備資料，它負責找模型。

1.1 一句話定義

TPOT = Tree-based Pipeline Optimization Tool（樹狀流程最佳化工具）。

它是一個 AutoML（Automated Machine Learning，自動化機器學習） 工具：把資料交給它，它會自動嘗試 「要用哪個演算法、資料要不要前處理、超參數怎麼設」，最後挑出表現最好的一條 機器學習管線 （Machine Learning Pipeline）。

名詞 英文 白話解釋
TPOT Tree-based Pipeline Optimization Tool 用「樹狀流程」的搜尋方式找出最佳管線的工具
AutoML Automated Machine Learning 把「選模型、調參數」這些人工步驟自動化
Pipeline（管線） sklearn Pipeline 一條「前處理 → 特徵處理 → 模型」的處理鏈
超參數 Hyperparameter 模型人為設定的參數（例如樹的數量、K 值），不是模型自己學的
個體 / 族群 individual / population 基因演算法裡的「一個模型」／「一批模型」

1.2 TPOT 到底幫你決定了哪三件事？

# 要決定的事 簡報原文的說法 具體例子
1 該選哪種演算法？ 隨機森林、神經網路、支持向量機？ RandomForestClassifier、SVC、KNeighborsClassifier
2 資料特徵該如何處理與篩選？ 前處理與特徵選擇 StandardScaler、MinMaxScaler、SelectPercentile、PCA
3 參數（Hyperparameters）該怎麼設定？ 參數設定 n_estimators=100、C=1.0、max_depth=5

考點：TPOT 幫你決定的是「怎麼做」（演算法＋前處理＋超參數），不包含「做什麼」—— 定義問題、收集資料、清理資料、判斷要用哪個評估指標，仍然是你自己的工作。

1.3 TPOT 在 AutoML 生態裡的定位

做法 誰決定模型 需要寫程式 可解釋性 適合情境
手寫 sklearn 你 要（每一種都要試） 高（你選的你懂） 已經知道該用什麼模型
TPOT 它（基因演算法搜尋） 要（但是寫「設定」而不是寫「模型」） 中（管線可讀，但組合可能很怪） 想快速知道「這份資料的天花板在哪」

1.4 最小可執行範例（六行看到成果）

# 本機實測環境：Python 3.11.16 / TPOT 1.1.0 / scikit-learn 1.9.1
from tpot import TPOTClassifier
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

tpot = TPOTClassifier(generations=5, population_size=20, scorers=["accuracy"],
                      cv=5, verbose=2, random_state=42,
                      n_jobs=4, processes=False)   # processes=False：本機必加
tpot.fit(X_train, y_train)
print("準確率：", tpot.score(X_test, y_test))

本機實測結果（同一份鳶尾花資料、random_state=42）：

項目 數值
測試集準確率 0.9474（36/38 題答對）
搜尋耗時 見第 9 章實測表（同一支腳本輸出）
最佳管線 見第 9 章「本機實測」

考點：TPOTClassifier 的 .fit() 是在背景跑基因演算法，不是一次訓練； 所以「同一段程式碼，每次跑出來的模型可能不同」——要可重現就一定要設 random_state。

2. 複習一下：什麼是機器學習（Machine Learning）？

簡報原話：「讓數據說話的技術」——傳統程式設計是人寫規則，機器學習是資料寫規則。

2.1 傳統程式設計 vs 機器學習

傳統程式設計 機器學習
誰寫規則 開發者寫下明確的規則與邏輯 我們提供「大量資料」和「對應的結果」，讓電腦自己找出隱藏的「規則」
輸入 規則 + 資料 資料（特徵 X）+ 答案（標籤 y）
輸出 結果 規則（模型）
遇到沒寫過的情況 直接失效 可以「猜」（泛化）
例子 if 氣溫 < 10: 提醒穿外套 看過 10 萬筆氣象資料後，自己學會判斷要不要提醒

一句話記法：

傳統程式設計：資料 + 規則  ──►  答案
機器學習    ：資料 + 答案  ──►  規則（模型）

2.2 實際應用：推薦系統

簡報舉的例子是 YouTube / IG 的推薦系統：

  1. 資料：你看過的影片、按過的讚、停留時間
  2. 答案：你「喜歡／不喜歡」的結果
  3. 規則：系統自己歸納出你的喜好 → 精準推薦你會喜歡的內容

2.3 三個一定要分清楚的名詞

名詞 英文 在本課的對應
特徵 feature / X 鳶尾花的「花瓣長度、花瓣寬度、花萼長度、花萼寬度」（iris.data，150×4）
標籤（答案） label / target / y 鳶尾花的品種（iris.target，0/1/2 三種）
模型 model TPOT 最後交給你的那條管線（Pipeline）

2.4 補上簡報沒寫、但一定會考的延伸

類型 有沒有答案（標籤） 例子 TPOT 對應類別
監督式學習（分類） 有，而且是類別 鳶尾花品種、鐵達尼號存活與否 TPOTClassifier
監督式學習（迴歸） 有，而且是數值 房價、銷售金額 TPOTRegressor
非監督式學習 沒有 分群（K-Means）、降維（PCA） TPOT 不做這件事

考點：本課的鳶尾花任務是「分類」，所以用 TPOTClassifier； 如果標籤是連續數值（例如房價），要換成 TPOTRegressor，並且評估指標會從 Accuracy 變成 RMSE。

2.5 用五行程式走一次監督式學習（本機實測）

from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = load_iris(return_X_y=True)                    # 150 筆、4 個特徵、3 個類別
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

model = DecisionTreeClassifier(random_state=42).fit(X_train, y_train)
print("訓練集分數：", model.score(X_train, y_train))   # 1.0000（自己考自己）
print("測試集分數：", model.score(X_test, y_test))     # 1.0（這份資料太簡單，兩邊都滿分）

本機實測輸出：

訓練集分數： 1.0
測試集分數： 1.0

咦？兩個都是 1.0？ 因為鳶尾花資料太簡單了——150 筆、4 個特徵、3 個類別幾乎線性可分， 不加 max_depth 的決策樹在測試集也能全對。要看得出「訓練分數虛高」的落差，需要更難的資料：

from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

Xn, yn = make_classification(n_samples=200, n_features=20, n_informative=3,
                             n_redundant=0, flip_y=0.25, class_sep=1.0,
                             random_state=42)          # 25% 的標籤被故意翻轉（雜訊）
Xn_tr, Xn_te, yn_tr, yn_te = train_test_split(Xn, yn, random_state=42)

model = DecisionTreeClassifier(random_state=42).fit(Xn_tr, yn_tr)
print("訓練集分數：", model.score(Xn_tr, yn_tr))   # 1.0000（把雜訊也背下來了）
print("測試集分數：", model.score(Xn_te, yn_te))   # 只有 0.84

本機實測輸出（完整結果見第 9 章「本機實測」）：

訓練集分數： 1.0
測試集分數： 0.84

考點：「訓練集分數」永遠不能當成模型的實力。要判斷一個模型好不好， 只能看它在沒看過的資料上的表現——這就是為什麼簡報第二步就要求 train_test_split。

3. 但資料科學家面臨了挑戰：模型調校的「排列組合」地獄

簡報原話：「這些選項的組合高達數萬種，光靠人工測試不僅極度耗時，更是不可能完成的任務。」

3.1 建立模型時，有太多變數需要決定

# 簡報列出的問題 白話 常見選項
1 該選擇哪種演算法？ 用哪個模型 隨機森林、神經網路、支持向量機、KNN、決策樹
2 資料特徵該如何處理與篩選？ 要不要標準化？要不要挑特徵？ StandardScaler、MinMaxScaler、SelectPercentile、PCA
3 參數（Hyperparameters）該怎麼設定？ 每個模型自己的旋鈕 n_estimators、max_depth、C、gamma、k

3.2 組合數到底有多少？本機實際算一次

只算「4 種演算法 × 3 種前處理 × 各 3 個超參數」（本機實測，combo.py）：

演算法 超參數組合 前處理 小計
RandomForest（3×3×3） 27 3 81
SVC（3×3×3） 27 3 81
KNN（3×2×2） 12 3 36
DecisionTree（3×3×3） 27 3 81
合計 279 種

而且這還只是「四個模型、每個三種參數」的玩具級搜尋空間。真實情況：

  • 前處理不只 3 種（缺值填補、編碼、特徵選擇、降維、多項式特徵……）
  • 每個模型都有更多超參數，而且常常是連續區間（不是三個離散值）
  • 還多了「要不要做集成（Ensemble）」「管線要接幾個步驟」這種結構性選擇

考點：組合數是相乘成長的。多一個要決定的維度，不是「多一點」，而是「乘上好幾倍」。 這就是簡報說的「排列組合地獄」。

3.3 人工調參要多久？本機實測

3.4 人工調參的四個真實痛點

# 痛點 說明
1 耗時 每次「換一個參數 → 重跑 → 記分數」都是人工迴圈
2 不可能窮舉 組合數是相乘成長，人工只能「挑幾個試試看」

考點：AutoML（TPOT）存在的理由，不是「人不會調參」，而是 「人工調參的覆蓋率太低，而且成本隨維度指數成長」。

4. 解決方案：隆重介紹 TPOT

簡報原話：「TPOT 就像是你專屬的 AI 研發助理。」你只要把整理好的資料交給它，它就會自動測試成千上萬種演算法與參數組合，最後篩選出準確度最高的模型，並把程式碼交還給你。

4.1 全名與定位

TPOT = Tree-based Pipeline Optimization Tool（樹狀流程最佳化工具）

字 意思
Tree-based 用「樹」的結構表示一條管線（每個節點是一個處理步驟，資料像水流一樣流過）
Pipeline 管線：前處理 → 特徵處理 → 模型，一連串步驟串起來
Optimization 最佳化：不是「隨便找一條」，而是搜尋表現最好的那條
Tool 工具：pip install tpot 就能用的 Python 套件

4.2 你給它什麼？它還你什麼？

你提供的 TPOT 回報你的
整理好的資料：X_train（特徵）、y_train（答案） 一條最佳管線（fitted_pipeline_）
預算：generations / population_size（或 max_time_mins） 每個候選模型的交叉驗證分數（evaluated_individuals）
評估指標：scorers=['accuracy'] 一個可以直接用來預測的模型（predict / predict_proba）

5. TPOT 的核心技術：基因演算法

簡報原話：「程式碼的物競天擇」——TPOT 借鑒生物演化的概念來尋找最佳模型。

5.1 簡報的四個步驟

步驟 簡報標題 簡報內容 對應的 TPOT 參數
1 初始族群 系統先隨機生成一批不同的 AI 模型（例如 100 個） population_size（每代幾個模型）
2 適者生存 對它們進行測試，準確率低的模型直接被淘汰 scorers（用什麼分數判定優劣）、cv（怎麼測）
3 交配與突變 將表現優異的模型特徵互相結合，或隨機微調參數，產生下一代模型 crossover_probability、mutate_probability
4 不斷迭代 經過多代的繁衍與優化，最後存活下來的就是效能最強的「冠軍模型」 generations（繁衍幾代）

5.2 名詞對照：生物學 ↔ TPOT

生物學 TPOT 白話
個體（individual） 一條管線（Pipeline） 例如「標準化 → 特徵選擇 → 隨機森林(100 棵)」
族群（population） 一代裡的所有管線 population_size=20 → 一代 20 條
世代（generation） 演化回合 generations=5 → 繁衍 5 代
適應度（fitness） 交叉驗證分數 scorers=['accuracy'] 時的 CV 平均準確率
交配（crossover） 兩條管線的步驟互換／合併 把 A 的前處理接上 B 的模型
突變（mutation） 隨機換掉一個步驟或改參數 把 n_estimators=100 改成 n_estimators=200
天擇（selection） 留下分數高的 分數低的不再繁衍

5.3 1.1.0 的實際演化參數（本機實測 get_params()）

參數 1.1.0 預設值 說明
population_size 50 每代族群大小（不是 100）
generations None 繁衍幾代；預設不設上限，改由 max_time_mins 控制
max_time_mins 60 搜尋的時間上限（分鐘）——預設就是 60 分鐘
max_eval_time_mins 10 單一管線的評估時間上限（分鐘）
crossover_probability 0.2 用「交配」產生下一代的比例
mutate_probability 0.7 用「突變」產生下一代的比例
survival_percentage 1 每代存活比例
cv 10 內部交叉驗證折數

考點：generations 與 max_time_mins 是兩種預算。只設 generations → 跑完就停； 只設 max_time_mins → 時間到才停（跑幾代不確定）。兩個都不設 → 它會跑最多 60 分鐘。 課堂上如果忘記設 generations，就會等很久，這是最常見的「為什麼我的 Colab 卡住了」。

5.4 演化過程長什麼樣？（verbose 的進度條）

verbose=2 時，TPOT 會在標準錯誤（stderr）印出進度條：

Generation: 100%|██████████| 5/5 [01:04<00:00, 12.89s/it]
verbose 值 會印出什麼
0 什麼都不印
1 只印最後結果
2 進度條（簡報畫面看到的那條）
3 進度條 + 每一代的最佳分數
4 / 5 更詳細（含 dask 的日誌）

考點：簡報說「下方會出現進度條，顯示目前演化到第幾代」——那個進度條就是 verbose=2 的輸出； 進度條的 5/5 就是 generations=5。

5.5 為什麼叫「樹狀」（Tree-based）？

因為一條管線在 TPOT 內部是一張有向圖（Directed Graph）：每個節點是一個 sklearn 元件 （Scaler、Selector、Classifier…），邊代表「資料從哪裡流到哪裡」。

這張圖允許「分叉再合併」（特徵工程常這樣做），所以比單純的「一條直線 Pipeline」更靈活。

5.6 基因演算法的兩個現實限制

限制 說明
不保證找到全域最佳 它是「隨機 + 擇優」，不是窮舉；預算太小就只是「逛一逛空間」
每次結果可能不同 除非固定 random_state，否則連「同一份資料、同一組參數」都會得到不同管線

考點：TPOT 的「最佳」= 在給定預算下的最佳。把 generations 從 2 加到 10， 通常分數會上升，但時間也線性增加——這就是「預算 vs 效果」的取捨。

6.3 這個比喻「沒有」告訴你的事（考點區）

比喻很好懂，但也容易讓人誤會。以下三件事 TPOT 不會幫你做：

誤會 事實
「有了 TPOT，我就不用懂機器學習了」 你還是要會：定義問題、選評估指標、切分資料、判讀結果

還有一個很現實的差異：

比喻 現實
「虛擬實驗室可以無限快」 每一次「跑圈」都是真的在訓練模型——資料越大越慢，所以才有 max_time_mins

from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

# 示範資料（真實的鐵達尼號資料欄位長這樣）
df = pd.DataFrame({
    "Pclass":  [3, 1, 3, 1, 3, 2, 3, 1],
    "Sex":     ["male", "female", "female", "female", "male", "male", "female", "male"],
    "Age":     [22.0, 38.0, 26.0, None, 35.0, None, 27.0, 54.0],
    "Fare":    [7.25, 71.28, 7.92, 53.10, 8.05, 13.00, 7.90, 51.86],
    "Embarked": ["S", "C", "S", "S", None, "S", "S", "C"],
    "Survived": [0, 1, 1, 1, 0, 0, 1, 0],
})

num_cols = ["Pclass", "Age", "Fare"]
cat_cols = ["Sex", "Embarked"]

prep = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale", StandardScaler())]), num_cols),
    ("cat", Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                      ("onehot", OneHotEncoder(handle_unknown="ignore"))]), cat_cols),
])

X = prep.fit_transform(df[num_cols + cat_cols])
y = df["Survived"].values
print(X.shape, "→", X.round(3).tolist()[:2])

9.4 步驟 4 第三部分：設定 TPOT 演化參數

簡報的程式碼：

簡報的參數 意思 在 1.1.0 的狀況
generations=5 繁衍 5 代 ✅ 仍支援（但預設值是 None，不是 5）
population_size=20 每代 20 個模型（共約 100 個） ✅ 仍支援（但預設值是 50）

1.1.0 的正確寫法（本機實測可跑）：

    generations=5, population_size=20,
    scorers=["accuracy"],   # 1.1.0 用 scorers 指定「適者生存」的指標
    cv=5,                   # 內部交叉驗證折數（1.1.0 預設 10）

    n_jobs=4,               # 平行度

from tpot import TPOTClassifier
from sklearn.datasets import load_iris
from sklearn.metrics import accuracy_score
from sklearn.model_selection import train_test_split

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

tpot = TPOTClassifier(
    generations=5, population_size=20, scorers=["accuracy"], cv=5,
    verbose=2, random_state=42, n_jobs=4, processes=False, scatter=False,

tpot.fit(X_train, y_train)
print("預測準確率：", accuracy_score(y_test, tpot.predict(X_test)))
print("最佳管線：", [name for name, _ in tpot.fitted_pipeline_.steps])

Q1：為什麼我跑出來不是 0.97？

10.4 課後三個練習

# 練習 你會觀察到什麼
1 把 generations 從 5 改成 10（或 population_size 改成 50） 時間變長、分數通常微幅上升 → 預算 vs 效果

def show_error(exc: BaseException, lines: int = 1) -> None:
    """印出錯誤型別、訊息，以及 traceback 的最後幾行（錯誤訊息要能照抄進筆記）。"""
    tb = traceback.format_exception(type(exc), exc, exc.__traceback__)
    print("  -> %s: %s" % (type(exc).__name__, exc))
    tail = [ln.rstrip() for ln in tb[-1 - lines:-1] if ln.strip()]
    for ln in tail[-lines:]:
        print("     " + ln)


def pipeline_steps(pipe):
    """回傳 [(名稱, 估計器)]；同時支援 sklearn Pipeline 與 TPOT 的 GraphPipeline。"""
    if hasattr(pipe, "steps"):
        return list(pipe.steps)
    if hasattr(pipe, "topo_sorted_nodes"):
        return [("step%d" % i, n) for i, n in enumerate(pipe.topo_sorted_nodes)]
    return []


def pipeline_to_code(pipe, indent="    "):
    """把最佳管線的每個步驟印成 sklearn 程式碼骨架（1.1.0 沒有 export()）。"""
    lines = []
    for name, est in pipeline_steps(pipe):
        args = []
        for key, val in sorted(est.get_params(deep=False).items()):
            if val is None or key == "random_state":
                continue
            text = repr(val)
            if len(text) > 40:
                text = text[:37] + "..."
            args.append("%s=%s" % (key, text))
        lines.append("%s%s = %s(%s)" % (indent, name, type(est).__name__,
                                        ", ".join(args)))
    lines.append("%s# 依 steps 的順序 fit/transform 串起來（sklearn Pipeline 語意）"
                 % indent)
    return "\n".join(lines)

# ========== 1. TPOT 是什麼 ==========
# Tree-based Pipeline Optimization Tool：AutoML 工具，用基因演算法找最佳管線
# 它決定：演算法 + 前處理 + 超參數；它不決定：問題定義、資料清理、評估指標

# ========== 2. 機器學習複習 ==========
# 傳統程式設計：資料 + 規則  → 答案
# 機器學習    ：資料 + 答案  → 規則（模型）
# 特徵 X（iris.data, 150×4）／標籤 y（iris.target, 3 類）

# ========== 3. 為什麼需要 AutoML ==========
# 4 演算法 × 3 前處理 × 3 參數 = 279 種組合（本機實測）
# GridSearchCV 18 條管線 × 5 折 = 90 次 fit → 3.94 秒；換成 279 種要 16 倍時間

# ========== 4. TPOT 的交付 ==========
# 給它 X_train / y_train → 還你 fitted_pipeline_（最佳管線）＋ 準確率

# ========== 5. 基因演算法四步驟 ==========
# 初始族群(population_size) → 適者生存(scorers+cv) → 交配/突變 → 迭代(generations)
# 生物學對照：個體=管線、族群=一代、適應度=CV 分數、天擇=留下高分

# ========== 6. 賽車比喻 ==========
# 零件=演算法、規格=超參數、跑圈秒數=CV 分數、改裝清單=管線節點
# 但：TPOT 不會幫你定義問題、清資料、解釋原因

# ========== 7. 鐵達尼號例子 ==========
# 標籤 = Survived；特徵 = 年齡/性別/艙等/票價
# 六個坑：缺失值、類別欄位、Pclass 是類別、文字欄位、尺度差異、資料洩漏
# 課堂改用鳶尾花的原因：零缺失、全數值、150 筆

# 步驟 1：colab.research.google.com → 新增筆記本

# ========== 9. 寫程式（步驟 3–5）==========
from tpot import TPOTClassifier
from sklearn.datasets import load_iris
from sklearn.metrics import accuracy_score          # 1.1.0 沒有 tpot.score()
from sklearn.model_selection import train_test_split

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

tpot = TPOTClassifier(generations=5, population_size=20, scorers=["accuracy"],
                      cv=5, verbose=2, random_state=42,      # 0.x 叫 verbosity
                      n_jobs=4, processes=False, scatter=False)  # 本機必加
tpot.fit(X_train, y_train)                            # 開始演化搜尋
print(accuracy_score(y_test, tpot.predict(X_test)))    # 0.9474（本機實測）
