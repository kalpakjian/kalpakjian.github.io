GAP 是什麼？為什麼現代 CNN 用它取代全連接層

系列第六篇。前五篇把卷積、激活、池化、全連接層都拆過了，這一篇回答兩個連在一起的問題：
① GAP 到底在做什麼？② 為什麼 2015 年之後的分類頭，幾乎都從「Flatten + 大 FC」換成「GAP + 一個小 Linear」？
GAP 本身只有一行公式、零參數；它換來的東西（參數量、尺寸自由、可解釋性）才是重點。
所有數字都是本機用 NumPy 算的（Python 3.15.1 / NumPy 2.5.4），原始輸出在附錄 G。

1. 舊寫法的代價

Conv → Pool → Flatten → FC(很大) → FC → Softmax

最後一層特徵圖 7×7×512，展平是 25,088 維。接 1,000 類：

25,088 × 1,000 + 1,000 = 25,089,000    ← 兩千五百萬個參數，只為了一個分類頭

2. GAP 是什麼：一個通道換一個數

GAP(X_c) = (1 / H·W) · Σ_i Σ_j x[i, j, c]
輸入 H × W × C  →  輸出 1 × 1 × C

三個要點：

  • 逐通道獨立：第 c 個通道只看第 c 張特徵圖，通道之間不混合（實測：逐通道迴圈等於 mean(dim=(1,2))）。
  • 通道數不變：C 進、C 出；變的只有 H、W（都變成 1）。
  • 沒有參數：沒有權重、沒有 bias，只有一次平均。

手算一個 4×4 的通道（值 1 到 16）：

(1 + 2 + … + 16) / 16 = 136 / 16 = 8.5

所以 4×4×1 → 1×1×1 = 8.5；7×7×512 → 512。

一個容易搞錯的地方：對整個張量取平均也會得到「一個數字」，但那會把「哪個通道貢獻的」混掉。
GAP 的輸出是長度 C 的向量，不是純量。

3. GAP 與一般 Average Pooling 的差別

項目一般 Average PoolingGAP
視窗大小固定小窗（如 2×2）整張特徵圖（H×W）
是否要 kernel size／stride要不需要
輸出尺寸7×7 → 3×3（2×2 窗、步幅 2）7×7 → 1×1
可學習參數00
常見位置CNN 中段分類頭之前
覆蓋範圍可能漏掉邊緣一定蓋滿整張圖

實測（7×7 的值 1–49）：

做法輸出平均
GAP1×125.00（49 格全用到）
AvgPool2d(2,2)3×321.00（只用 36 格，最後一列一行被丟掉）
AvgPool2d(3,3)2×221.00（同樣只用到 36 格）
AvgPool2d(7,7)1×125.00 ← 這時它就是 GAP

換句話說：GAP 就是「視窗等於整張圖」的平均池化，所以它不需要 kernel size 與 stride；而一般池化會因為不整除而漏掉邊緣——這是很多人以為「兩者結果一樣」卻對不上的原因。

4. 換成 GAP 之後，參數差多少

分類頭參數
Flatten(25,088) → Linear(1000)25,089,000
GAP(512) → Linear(1000)513,000

差 48.9 倍，而兩者的輸出完全一樣（1,000 個 logits）。GAP 自己貢獻 0 個參數——它只是把 512 張 7×7 各自平均掉。

5. 這在真實模型上有多大？

我把三個架構的參數量逐層加起來（MobileNetV2 依官方 block 規格重算）：

模型分類頭參數全部參數佔比
VGG16123,642,856138,357,54489.4%
MobileNetV2（1.0、1000 類）1,281,0003,487,81636.7%
ResNet-502,049,00025,557,0328.0%

VGG16 有將近九成參數卡在最後三層全連接（其中兩層是 4096×4096）。MobileNetV2 的 36.7% 對應「全連接分類頭約佔 37%」這個常被引用的數字；差額來自是否把 BatchNorm 的 γ/β 算進去（+17,056）。

6. 好處二：輸入尺寸不再綁死

特徵圖GAP 之後展平之後
7×7×51251225,088
8×8×51251232,768
14×14×512512100,352

GAP 的輸出長度只取決於通道數 C，所以同一個分類頭可以吃不同解析度的特徵圖（7×7、14×14、28×28 都通）。展平的長度是 H×W×C，換尺寸就得換分類頭、權重全部重來。這也是全卷積網路（FCN）能在任意尺寸影像上跑的原因。

7. 好處三：對位移更穩健

把同一張 7×7 特徵圖往右移一格（循環位移），實測：

做法結果
GAP25.0 → 25.0（差 0.0）
Flatten49 個位置全部改變，L2 距離 17.15

GAP 的輸出與位置無關，所以「同一個特徵往旁邊挪幾格」對它沒有任何影響。這對分類特別合理：你只需要知道「有沒有貓耳朵」，不需要知道它在第幾行第幾列。代價也就在這裡：需要精確位置的任務（物件偵測、語意分割、關鍵點估計）不能只用 GAP。

8. 好處四：可解釋性——GAP 的權重就是 CAM 的權重

分類頭是 Linear(C → K)，每一列 w[k] 就是「類別 k 對每個通道的重視程度」。把它乘回每個通道的特徵圖再相加，就是 CAM（class activation map）：

logit(k) = Σ_c w[k, c] · GAP(A_c)
         = (1 / H·W) Σ_i Σ_j Σ_c w[k, c] · A_c[i, j]
         = CAM_k 的空間平均

兩邊在數學上完全相等，實測最大差 2.22e-16（浮點誤差）。所以：

  • 不需要改模型就能產生「模型在看哪裡」的熱圖：把 CAM_k 放大回原圖尺寸即可（Grad-CAM 是同一條思路的推廣）。
  • GAP 不是「把資訊丟掉」而已，它讓通道權重變成可視化的空間權重。

完整推導、2×2 手算例子、以及 Grad-CAM 的關係，見 CAM：用 GAP 算出模型在看哪裡。

9. 典型現代設計

Conv blocks（可訓練、保留空間）
→ GAP（0 參數，把 H×W 收成 1）
→ Linear(C → num_classes)
→ Softmax

實例：

7×7×512 → GlobalAvgPool → 512 → Linear(512 → 1000) → Softmax → 1000 類機率

GoogLeNet（2014）是較早用 GAP 取代末端大 FC 的代表；ResNet、MobileNet、EfficientNet 都沿用這個頭。差別只在骨幹怎麼設計。

10. 但全連接層沒有消失

情境還需要 FC 嗎
分類（C → K）需要，但只是一層小 Linear
物件偵測／分割／關鍵點不能只靠 GAP（位置資訊不能丟）
度量學習、檢索、多標籤常接輕量 FC 當 embedding／任務頭
表格資料本來就用 FC

換句話說：被淘汰的是「大型」全連接層，不是全連接層本身。

11. 變體與實作注意

變體做法什麼時候用
GAP每通道取平均分類頭的預設
GMP（global max）每通道取最大想保留「最強響應」
GAP + GMP 串接兩者拼接成 2C細粒度分類
GeM（generalized mean）介於平均與最大之間檢索、需要可調池化強度

實作上三個常踩的點：

  1. 維度要對：x.mean(dim=(2, 3))（PyTorch）或 x.mean(axis=(1, 2))（NumPy，無 batch 維），不是 dim=1。
  2. 形狀是 (N, C, 1, 1)：很多實作會 flatten(1) 或 squeeze() 才接 Linear。
  3. AdaptiveAvgPool2d(1) 可以取代固定視窗的 AvgPool2d，輸入尺寸隨便換都不報錯。

兩個實測數字（4×4 特徵圖、值 1–16）：GAP = 8.50、GMP = 16.00——同樣 0 個參數，留下的是完全不同的資訊。

12. 六個常見誤解

誤解事實
GAP 有參數沒有；參數在後面的 Linear
用了 GAP 就沒有全連接層通常還有一層 Linear(C → K)；GAP 取代的是「大 FC」
GAP 與 2×2 平均池化的結果一樣不一樣：池化窗口不整除時會漏掉邊緣（7×7 → 3×3 只用到 36 格）
GAP 一定比 Flatten 準不一定；它換來參數與尺寸自由，代價是空間資訊
GAP 可以放網路中間可以（例如 SE 模組的通道注意力），但會把空間壓成 1×1
GAP 讓模型「完全平移不變」對整體平均不變；對局部結構仍敏感（這是好事）

附錄 B 常見錯誤

  1. 對整個張量取平均：那是 1 個數，不是 C 個數。
  2. 在 GAP 後面又接 Flatten：(N, C, 1, 1) 攤平就是 (N, C)，多此一舉。
  3. 維度搞錯：mean(dim=1) 會把通道平均掉，正好相反。
  4. 以為 2×2 平均池化可以代替 GAP：覆蓋率與輸出形狀都不同。
  5. 拿 VGG16 的參數量當「CNN 都很大」的例子：它的問題正是那 89.4% 的分類頭。
  6. 以為 GAP 只能用於分類：通道注意力（SE）、音訊、點雲都用得到。
