五、十課的原理要點

L1｜AutoML 的定位與原理總覽

  • AutoML 自動化的三個層次：自動前處理／自動模型選擇／自動超參數
  • 為什麼這三件事「可以」自動化：目標可量化 ＋ 候選可列舉
  • 三個能力邊界：不能替你定義問題、不能替你取得好資料、不能保證可解釋
  • 何時不該用 AutoML

L2｜迴歸問題與誤差的本質

  • 殘差是唯一原料；差別只在「如何把殘差變成非負」
  • 平方 vs 絕對值：凸性造成的極端值放大
  • RMSE ≥ MAE 恆成立；比值＝誤差離散度診斷器
  • R² 是「相對於猜平均數」的相對指標
  • MAPE 三個數學地雷：零分母／小分母／不對稱

L3｜分類問題與評估的本質

  • 混淆矩陣是四格資訊結構，所有分類指標都是它的函數
  • Accuracy 在不平衡資料上失效的數學原因
  • AUC 衡量的是排序能力，不是閾值下的正確率
  • 閾值是可以調的決策變數，不是模型屬性
  • Precision / Recall 的取捨取決於「哪一種錯誤更貴」

L4｜資料與任務轉化

  • 切分方式＝你對「未來」的假設（IID vs 分佈漂移）
  • 三種洩漏：目標洩漏／時間洩漏／前處理洩漏
  • 前處理必須包進 Pipeline 的因果理由
  • 特徵工程的原理：滯後、滾動窗、洩漏窗
  • 類別不平衡的根源在資料分佈，不在模型

L5｜自動搜尋的原理

  • 組合爆炸：10 個超參數 × 各 5 值 ≈ 千萬組合
  • 四種策略的取捨：窮舉／隨機／貝葉斯／族群式
  • 交叉驗證的統計意義與 K 折的選擇
  • CV 選擇偏誤：搜尋越久，CV 分數越樂觀
  • primary metric 的選擇決定搜尋方向

L6｜遺傳規劃與 TPOT 的原理

  • 搜尋對象是「整條管線的樹狀結構」，不是參數向量
  • 演化四機制：選擇、交叉、突變、精英保留
  • 選擇壓力 vs 多樣性：早熟收斂的成因
  • 多目標優選：分數 vs 複雜度的 Pareto 取捨
  • 預算三要素：族群大小 × 世代數 × 折數；回報遞減
  • 白盒管線的價值：可檢視、可交付、可維護

L7｜集成與多引擎比較的原理

  • 集成為何有效：降低變異數／降低偏差
  • 兩條哲學：演化搜尋單一最佳管線 vs 廣搜多模型再堆疊集成
  • Leaderboard 的統計意義：CV 分數有變異，排名不穩定
  • 為何表格資料上樹模型幾乎無敵
  • 沒有免費午餐：分數／時間／透明度／可維護性的四角取捨

L8｜雲端 AutoML 的原理與取捨

  • 雲端賣的是算力彈性、治理審計、MLOps 生命週期
  • 服務參數的原理對應：primary metric＝搜尋目標、early termination＝邊際效益、timeout＝預算上限、featurization＝自動前處理
  • 成本結構：短時訓練 vs 常駐端點（端點一開就是月費）
  • 上雲的五個判準：資料量、算力需求、合規、團隊規模、生命週期長度

L9｜可解釋性、漂移與負責任 AI 的原理

  • 解釋方法本質都是「擾動＋觀察」：Permutation／SHAP／PDP
  • 相關不等於因果（特徵重要性的最大陷阱）
  • 漂移＝分佈的統計檢定（PSI／KS 在測什麼）
  • 資料漂移 vs 概念漂移
  • 公平性存在定義衝突：不可能同時滿足所有定義

L10｜從實驗到生產

  • 三道鴻溝：環境可重現性／資料分佈改變／監控缺失
  • 可重現性三要素：程式、資料、環境
  • 模型是會衰減的資產；重訓的觸發條件
  • 上線後監控什麼、多久看一次
  • 風險與成本評估框架

三、原理 I｜AutoML 自動化了什麼（45 分）

3.1 傳統機器學習流程的六個步驟

① 定義問題 → ② 取得資料 → ③ 清理與前處理 → ④ 選模型 → ⑤ 調超參數 → ⑥ 評估與部署

把這六步按「勞力密集程度」排一下，會發現 ③④⑤ 是重複性最高、最耗人力的三步：

步驟 誰在做 痛點
① 定義問題 人 無法自動化（需要領域知識）
② 取得資料 人 無法自動化（需要管道與權限）
③ 清理與前處理 人 大量重複：填缺失、編碼、標準化
④ 選模型 人 靠經驗與直覺，容易漏掉好模型
⑤ 調超參數 人 組合爆炸，人工試不完
⑥ 評估與部署 人 需要判斷（指標選擇、上線策略）

3.2 三個自動化層次（本課核心）

層次 自動化什麼 具體動作
自動前處理 特徵的加工 缺失值填補、類別編碼、標準化、特徵選擇
自動模型選擇 用哪個演算法 在候選演算法中比較並挑選
自動超參數 用哪組參數 搜尋參數組合

注意：這三層是同一個搜尋問題的不同維度。 把它們合起來看，AutoML 搜尋的其實是「一條完整的管線」。

3.3 為什麼這三件事可以自動化（兩個前提）

前提一：目標可量化。 要搜尋，就需要一個「誰比較好」的判準。所以 AutoML 的前提是：能把成功變成一個數字。

前提二：候選可列舉。 搜尋空間必須是「有限的、可執行的」——每個候選都要真的能跑起來、算得出分數。

兩個前提的推論：

情況 能不能用 AutoML
目標可量化、候選可列舉 ✅ 最適合
目標可量化，但候選無法列舉 ⚠️ 只能用來輔助，不能全自動
目標無法量化（例如「讓客戶開心」） ❌ AutoML 幫不上忙

一句話記住：AutoML 自動化的是「搜尋」，不是「判斷」。

3.4 一個常見誤解

誤解 正確理解
「AutoML 會自己找出該解決什麼問題」 問題必須由人定義；AutoML 只解你給它的問題
「AutoML 不需要資料清理」 它會自動做清理，但自動的選擇不一定對；髒資料仍然會毀掉結果
「AutoML 一定比人做得好」 它比「沒時間調參的人」好；不一定比「有經驗又肯花時間的人」好

四、原理 II｜三個能力邊界（15 分）

邊界 意思 不守這條邊界的後果
不能替你定義問題 任務類型（分類／迴歸）、目標欄位、成功標準都要人給 任務選錯，分數再高也是白做
不能替你取得好資料 資料的代表性、標籤品質、涵蓋範圍 垃圾進、垃圾出；模型只是在學偏誤
不能保證可解釋 搜尋目標只有「分數」，沒有「可解釋性」 找到的模型可能沒人能解釋，法規或業務上不能用

這三條邊界背後的同一個道理： AutoML 優化的是你給它的目標。目標沒定義好、資料沒代表性、沒要求可解釋性， 它就會「忠實地」給你一個符合你要求、但不符合你真實需求的答案。

三、原理 I｜殘差是唯一原料（45 分）

3.1 迴歸問題的定義

預測連續值。判斷方式不是「資料看起來像不像數字」，而是目標欄位的語意： 「這個值可以取中間值嗎？」可以 → 迴歸；不可以 → 分類。

3.2 誤差 = 殘差 = y − ŷ

  • 殘差有正有負，直接加總會互相抵消（正負抵消後平均值恆為 0）。
  • 所以任何誤差指標都必須先做一次「把殘差變成非負」的加工。

3.3 三種加工方式 → 三個指標家族

加工方式 指標 數學式 性質
取絕對值再平均 MAE (1/n)·Σ|y−ŷ| 對所有誤差等權重
平方再平均（再開根號） MSE / RMSE √[(1/n)·Σ(y−ŷ)²] 對大誤差加權，開根號後單位回到原單位
除以真值再平均 MAPE (100/n)·Σ|(y−ŷ)/y| 無單位，但依賴分母

關鍵句：三個指標的原料完全相同（同一組殘差），差別只在「怎麼把殘差變成非負」。 所以「用 RMSE 的模型」和「用 R² 的模型」這種說法在原理上不成立——模型只有一個，指標可以換很多個。

3.4 為什麼要開根號？

MSE 的單位是「原單位的平方」（例如「萬元²」），無法與業務對話。 開根號後 RMSE 的單位回到原單位（「萬元」），這是 RMSE 比 MSE 常被使用的原因。

3.5 單位與尺度的兩個推論

  • RMSE / MAE 有單位 → 同一個模型換一個單位（元 → 萬元），數值就變 10000 倍。
  • 因此 RMSE 不可跨資料集、跨單位比較；R² 與 MAPE 無單位，相對可比。

四、原理 II｜平方的凸性：極端值的放大（15 分）

4.1 數學直覺

平方函數是凸函數：誤差從 1 變 2（2 倍），平方後從 1 變 4（4 倍）； 誤差從 1 變 10（10 倍），平方後變成 100（100 倍）。

推論：RMSE 對「少數極端誤差」的敏感度遠高於 MAE。

4.2 RMSE ≥ MAE 恆成立

由變異數的定義可證明：

RMSE² = MAE² + Var(|殘差|)
⇒ RMSE ≥ MAE（等號成立 ⟺ 所有 |殘差| 完全相同）

所以兩者的差距本身就是資訊：

RMSE / MAE ≈ 1        → 誤差大小均勻
RMSE / MAE 明顯 > 1   → 少數樣本主導整體表現（誤差分佈不均）

一句話記住：RMSE 與 MAE 的差距，是「離群值診斷器」。

4.3 實務含義

情境 該用哪個 理由
極端誤差成本極高（如安全庫存、金融風險） RMSE 讓大錯被放大，模型會優先修大錯
誤差成本大致線性（如一般需求預測） MAE 不讓少數極端值綁架模型
需要向非技術主管報告 兩個都給 差距本身就是「資料乾淨度」的訊號

五、原理 III｜R² 與「相對於什麼基準」（35 分）

5.1 R² 的定義

R² = 1 − SS_res / SS_tot
   SS_res = Σ(y − ŷ)²        ← 你的模型犯的錯
   SS_tot = Σ(y − ȳ)²        ← 「一律猜平均數」犯的錯

R² 的基準不是 0，而是「猜平均數」這個笨策略。

5.2 三個直接推論

  1. R² 可以為負：模型比「一律猜平均數」還爛時，R² < 0。
  2. R² 無單位：分子分母單位相同，換單位（元 → 萬元）R² 不變。 → 所以 R² 相對可跨資料集比較，RMSE 不可以。
  3. R² 是相對指標，不是誤差大小：R² = 0.9 不代表誤差小， 只代表「比猜平均好 90% 的變異數」；若 y 本身變異很小，R² 可能很好看但毫無實用價值。

5.3 R² 與 RMSE 的代數關係

RMSE² = (1 − R²) · Var(y)

用途：看到 R² 時，立刻可以反推 RMSE（只要知道 y 的變異數）。 陷阱：用同一份資料比較兩個模型時，R² 與 RMSE 的排序永遠一致（因為 Var(y) 是常數）。 所以「R² 和 RMSE 給了不同結論」通常代表你用了不同的測試集。

5.4 為何要兩個都看

指標 回答的問題
RMSE / MAE 錯多大（業務語言）
R² 比笨方法好多少（相對貢獻）
MAPE 錯的比例（可跨商品比較）

一句話記住：RMSE 說「痛多少」，R² 說「比笨蛋聰明多少」，MAPE 說「比例上錯多少」。

  誤差極度不均         17.9109    8.8000      2.0353

要點：比值 ≈ 1 → 誤差均勻；比值越大 → 少數樣本主導。 行動：比值高時，去查那些樣本（資料錯誤？極端事件？），而不是繼續調模型。

6.4 示範 ④ MAPE 的三個數學地雷

實測輸出：

  地雷 1｜分母可以為 0：
    y_true=[0, 100], y_pred=[1, 100] → MAPE = inf
    絕對誤差只有 1，MAPE 卻是無限大。

  地雷 2｜小分母爆炸：
    y_true=[1, 1000], y_pred=[2, 1000] → MAPE = 50.00%
    整體只錯 1 個單位，MAPE 卻報 50%。

  地雷 3｜不對稱：低估有上限 100%，高估無上限：
    低估到極限 y_true=100, y_pred=0     → MAPE = 100.00%
    高估 10 倍  y_true=100, y_pred=1000 → MAPE = 900.00%

要點：MAPE 唯一的優點是無單位，代價是上面三個地雷。 → 使用前提：真值恆為正，且沒有接近 0 的觀測。

6.5 示範小結（自己抄一次）

同一組殘差
   ├─ 取絕對值平均   → MAE   （等權重）
   ├─ 平方再開根號   → RMSE  （放大極端值）
   ├─ 除以真值平均   → MAPE  （無單位，但有地雷）
   └─ 與猜平均比較   → R²    （相對指標，可為負）

七、原理 IV｜指標是選擇，不是事實（20 分）

7.1 決策表（本課核心產出）

情境 首選 次選 理由
誤差成本與誤差大小成正比 MAE RMSE 不要讓少數極端值綁架模型
大錯的代價遠高於小錯 RMSE MAE 需要放大極端值
要跨商品／跨門店比較 MAPE R² 無單位；但先確認無 0 值與小分母
要向高層說明「比現況好多少」 R² RMSE 相對貢獻的語言
要寫進 SOP 的絕對誤差容忍度 RMSE / MAE — 需要原單位
有 0 值或負值 MAE / RMSE — MAPE 直接失效

7.2 四個常見誤解（要主動破除）

誤解 正確理解
「R² 越高模型越好」 R² 高可能只是 y 的變異小；要看 RMSE 是否有業務意義
「RMSE 越小越好」 不能跨資料集比；且要確認測試集是否代表性
「MAE 比 RMSE 好，因為不受極端值影響」 這是特性不是優點；大錯不罰，模型就不會修大錯
「多指標都算一遍最保險」 指標越多越容易挑到好看的那個（多重比較問題）

7.3 為何不要只看 R²（給主管的一頁）

  1. R² 是相對指標，無法回答「錯多少錢」。
  2. R² 對 y 的變異極敏感：同一個模型在不同資料集上 R² 可能差很多。
  3. R² 不能比較不同資料集上的「誤差大小」。 → 建議：對外報 RMSE／MAE（業務語言），對內報 R²（技術語言）。

三、原理 I｜混淆矩陣：四格資訊結構（40 分）

3.1 分類問題的定義

預測離散類別。判斷方式不是「資料看起來像不像類別」，而是：

這個值可以取中間值嗎？ 不可以 → 分類；可以 → 迴歸。

3.2 四格的業務含義

                     預測：負          預測：正
真實：負      TN（真陰性）        FP（假陽性，誤報）
真實：正      FN（假陰性，漏報）   TP（真陽性）
格子 業務語言 通常誰最在意
TP 抓對的 業務方
FP 誤報（狼來了） 成本方（浪費資源、嚇到客戶）
FN 漏報（放過壞人） 風險方（真正的損失）
TN 正確放過的 沒人提，但它佔了大多數

關鍵：這四格的「成本」通常不相等。 分類問題的難點不在「預測準不準」，而在「哪一種錯更貴」。

3.3 所有分類指標都是這四格的函數

指標 公式 它回答的問題
Accuracy (TP+TN) / 全部 整體對了幾個？
Precision TP / (TP+FP) 抓到的人裡，有多少是真的？
Recall（召回率） TP / (TP+FN) 真的裡面，抓到了多少？
F1 2PR/(P+R) Precision 與 Recall 的折衷
Specificity TN / (TN+FP) 負類裡，正確放過了多少？
AUC （不是四格的函數，見原理 III） 排序能力

一句話記住：分類指標沒有「哪個最好」，只有「哪個對應你的成本結構」。

四、原理 II｜Accuracy 為什麼會騙人（20 分）

4.1 數學理由

設正類比例為 p。一個「什麼都不做、全部猜負類」的模型：

Accuracy = 1 − p

當 p 很小（例如 5%），這個笨模型就有 95% 的 Accuracy。

更糟的是：Accuracy 是四格的平均值，而多數類佔了絕大多數格子。 所以 Accuracy 幾乎只在衡量「你有沒有猜對多數類」，對少數類幾乎不敏感。

4.2 這個陷阱的實務後果

現象 後果
模型報「準確率 96%，比現況進步」 但少數類幾乎沒抓到
全部猜負類也有 95% 所謂的「進步」只有 1 個百分點
上線後才發現漏掉大量目標客戶 因為開發階段只看 Accuracy

4.3 一個可以直接用的檢查

跑模型前，先算「多數類基線」的 Accuracy。 如果你的模型沒有明顯超過它，那個模型基本沒有價值。

推論：只要正類比例不是接近 50%，就不應該用 Accuracy 當主要指標。

五、原理 III｜門檻 vs AUC（35 分）

5.1 門檻是「決策變數」，不是模型屬性

分類器輸出的通常不是類別，而是一個分數（機率或評分）。 把分數變成類別，需要一個門檻——而門檻是你選的。

門檻升高 → 少預測正類 → Precision ↑、Recall ↓
門檻降低 → 多預測正類 → Precision ↓、Recall ↑

這個反向移動是數學必然，不是模型不好。

5.2 門檻該設在哪？取決於成本

情境 該偏哪邊 理由
漏報代價極高（詐騙、重症篩檢） 偏低門檻 寧可誤報，不能漏報
誤報代價極高（寄送成本、打擾客戶） 偏高門檻 寧可漏報，不要誤報
兩者差不多 看 F1 或業務 KPI 折衷

門檻不是模型的參數，是業務決策。 這件事在課堂上很容易被跳過。

5.3 AUC 衡量的是「排序能力」

AUC 只問一個問題：

隨機抽一個正類和一個負類，模型把正類排在負類前面的機率是多少？

AUC 意思
0.5 等於亂猜
0.7～0.8 可用
0.8～0.9 好
1.0 完美排序

三個重要性質：

  1. 與門檻無關：改門檻，AUC 完全不變。
  2. 與類別比例無關：換一個不平衡程度不同的資料集，AUC 仍可比。
  3. 只反映排序：AUC 高不代表你現在的門檻設對了。

5.4 三個指標各說一句話

指標 它其實在說
Accuracy 「我整體猜對的比例」（會被多數類綁架）
Recall 「少數類我抓到了多少」（不平衡時最誠實）
AUC 「我的排序能力如何」（與門檻、比例都無關）

七、原理 IV｜不平衡的根源與四種對策（15 分）

7.1 根源：不是模型，是資料分佈

不平衡影響的是兩件事：

  1. 門檻該設在哪（因為分數分佈偏了）
  2. 指標該選哪個（因為 Accuracy 失效了）

它不影響模型的排序能力（AUC）。所以：

先換指標 → 再調門檻 → 最後才考慮重採樣。

7.2 四種對策與適用順序

順序 對策 原理 什麼時候用
1 換指標 用 Recall／AUC／PR-AUC 取代 Accuracy 幾乎所有不平衡場合（零成本）
2 調門檻 直接改變決策邊界 你已經有機率輸出時（零成本）
3 加權／重採樣 讓模型更在意少數類 前兩項做完仍不夠時
4 換問題定義 例如把「預測」改成「排序」 少數類極少（<0.1%）時

7.3 常見誤解

誤解 正確理解
「不平衡會讓模型學不會」 模型學得會排序；是評估與門檻出問題
「先做 SMOTE 再說」 重採樣會改變分佈，也可能引入洩漏（必須只在訓練集做）
「AUC 高就沒事」 AUC 高但門檻沒調，業務表現照樣差
「準確率 95% 很好」 要看多數類基線是多少

一句話記住：不平衡是「決策問題」，不是「模型問題」。

  2. 不是。這是數學必然：門檻升高 → 少預測正類 → TP 減少、FP 減少 → Precision 升、Recall 降。 門檻是決策變數，不是模型屬性。
  3. 不會。AUC 0.93 代表排序能力好；Recall 低代表門檻設太高。 診斷方向是「調門檻」，不是「換模型」。
  4. Accuracy 是四格的平均，而四格的比例會隨類別比例改變 → 不可跨資料集比較。 AUC 只計算「正負類配對的排序正確率」，把類別比例消掉了 → 可比較。
  5. 換指標 → 調門檻 → 加權／重採樣 → 換問題定義。 前兩項零成本、且針對真正的問題（評估與決策）； 重採樣會改變資料分佈、可能引入洩漏，所以放後面。

九、練習

  2. 想一個你熟悉的業務場景，寫下 FP 與 FN 各是什麼，並判斷哪一種更貴。 然後推導出：這個場景的門檻應該偏哪邊。

三、原理 I｜切分方式＝你對未來的假設（40 分）

3.1 模型只能學到「訓練資料的分佈」

這句話有個直接的推論：

你怎麼切分資料，就等於你假設「未來長得像什麼」。

3.2 兩種切分，兩種假設

切分方式 隱含假設 適用場合
隨機切分 未來與現在來自同一個分佈（IID） 資料沒有時間性（例如：影像分類）
時間切分 未來是「接在現在後面」的，分佈可能改變 有時間性的資料（銷售、股價、客戶行為）

3.3 隨機切分為什麼會「作弊」

當資料有時間性時，隨機切分會：

  1. 把未來的資料混進訓練集；
  2. 於是模型「看過未來」，測試分數被系統性高估；
  3. 上線後才發現真實表現遠低於報告。

記住這個症狀：如果離線分數很好、上線卻很差，第一個要檢查的就是切分方式。

3.4 判斷流程

資料有沒有時間性？
 ├─ 沒有（每一筆獨立） → 隨機切分
 └─ 有 → 時間切分（用過去預測未來）
          └─ 若還需要驗證模型穩定性 → 滾動式切分（多個時間窗）

四、原理 II｜三種洩漏與因果順序（25 分）

4.1 洩漏的定義（用因果，不用技巧）

洩漏 = 在「預測的那一刻」拿不到的資訊，被用進了模型。

這個定義不需要懂任何技巧，只需要問一個問題：

在真正要預測的那個時間點，這個資訊存在嗎？

4.2 三種洩漏

類型 長什麼樣 為什麼錯
目標洩漏 特徵裡混進了「結果才知道」的欄位（結案狀態、退款金額） 預測當下這個欄位還不存在
時間洩漏 用未來資料訓練（隨機切分時間序列資料） 因果順序顛倒
前處理洩漏 用全部資料算平均／標準差／挑特徵，再切分 訓練時「看過」測試集

4.3 為什麼前處理洩漏最難察覺

目標洩漏通常很明顯（欄位名字就看得出來）。 前處理洩漏藏在「一行看起來無害的程式碼」裡：

# ❌ 錯：先標準化，再切分
X_scaled = scaler.fit_transform(X)        # ← 用了全部資料的統計量
X_tr, X_te = train_test_split(X_scaled)

# ✅ 對：先切分，前處理包進管線
X_tr, X_te = train_test_split(X)
pipe = Pipeline([("scaler", StandardScaler()), ("model", ...)])
pipe.fit(X_tr)                            # ← 統計量只從訓練集算

錯的那一版不會報錯、不會變慢，只會給你一個漂亮但假的數字。

4.4 為什麼一定要包進管線（真正理由）

不是「因為教科書這樣寫」，而是：

管線保證「每一個前處理步驟的參數，都只用訓練資料估計」。 交叉驗證時，每一折都會重新估計一次 → 完全不會看到驗證折的資訊。

這是因果順序的落實：預測時你能用的，只有訓練時看過的東西。

六、原理 III｜特徵工程的原理（30 分）

6.1 三種時間相關特徵

特徵類型 做法 陷阱
滯後（Lag） 用 t−1、t−2 的值當特徵 滯後期數要對得上「預測時真的拿得到」的時間
滾動窗（Rolling） 過去 N 期的平均／標準差 窗口必須不含當期（否則就是洩漏）
累計（Cumulative） 至今累計值 常與「未來才知道的總量」混淆

6.2 判斷準則：時間軸上畫一條線

過去 ────────────┤ 現在（預測點）──────────── 未來
   ✅ 可以用        │        ❌ 不能用

任何跨越這條線的特徵，都是洩漏。

6.3 常見的「假特徵」

假特徵 為什麼是洩漏
客戶「總消費金額」（含預測期之後的消費） 跨越了預測點
「本月最終」銷售量（用來預測本月） 當期結果
用全期間平均填補缺失值 用了未來的統計量
用「整個資料集」做目標編碼 用了測試集的標籤分佈

一句話記住：特徵工程的第一原則不是「有沒有用」，而是「當時拿不拿得到」。

7.1 不平衡的兩種來源

來源 說明 對策方向
真實不平衡 少數類本來就少（詐騙、罕見病） 改指標、調門檻
取樣偏誤 少數類被系統性漏收（某些客戶不回覆） 先修資料收集，不是修模型

7.3 重採樣的三個陷阱

陷阱 說明

三、原理 I｜組合爆炸與搜尋成本（35 分）

3.1 成本公式（本課最重要的一行）

搜尋成本 ≈ 候選數 × 交叉驗證折數 × 單次訓練成本

3.2 候選數是「相乘」的

實測（示範 ①）：一個常見的樹模型參數網格

    max_depth            有 11 個候選值
    min_samples_leaf     有  7 個候選值
    min_samples_split    有  4 個候選值
    max_features         有  5 個候選值

  候選總數 = 1540 組
  若每組用 3 折交叉驗證、每折 0.05 秒 → 約 3.9 分鐘
  若再加一個參數（10 個值）→ 15400 組，時間變 10 倍

只要多一個參數，成本就乘以它的候選數——這就是窮舉不可行的原因。

3.3 三個乘數的實際影響

乘數 增加時會怎樣 常被忽略的地方
候選數 相乘成長 加一個參數不是「多一點」，是「多好幾倍」
折數 線性成長 折數太少分數不穩，太多則成本翻倍
單次訓練成本 隨資料量成長 資料量才是最大的隱形乘數

實務經驗：搜尋的瓶頸通常是「要評估很多條管線 × 每條都要做 K 折」， 而不是「訓練一個模型很慢」。

四、原理 II｜四種搜尋策略的取捨（20 分）

策略 怎麼做 優點 代價
窮舉（Grid） 全部組合都試 可預期、可重現 維度高就爆掉
隨機（Random） 隨機抽候選 高維時效率高、預算可控 不保證找到最好
貝氏（Bayesian） 用歷史結果建代理模型，引導下一點 樣本效率最高 實作較複雜、難平行
族群式（Evolution） 族群＋選擇＋交叉＋突變 能搜尋「結構」而不只參數 需要足夠預算（見第 6 課）

4.1 為什麼隨機搜尋在高維不輸窮舉

窮舉在每個維度上都用固定間隔，當「真正重要的維度只有少數幾個」時， 窮舉把大量預算浪費在不重要的維度上。隨機搜尋則把預算攤到整個空間。

實測（示範 ④）：

  窮舉（1540 組候選）：CV R² = 0.5846，耗時 4.08 秒
  隨機（  60 組候選）：CV R² = 0.5670，耗時 0.16 秒

  → 隨機只用了 3.9% 的預算，CV 分數差距 0.0176

一句話記住：搜尋的第一原則不是「找到最好」，而是「在預算內找到夠好」。

五、原理 III｜交叉驗證、回報遞減、CV 選擇偏誤（30 分）

5.1 交叉驗證的統計意義

K 折交叉驗證做的是：把資料切成 K 份，每次留一份當驗證，其餘當訓練，最後取平均。

它解決的問題：單一次切分的分數變異太大，不足以支撐決策。

折數 特性
3 快，但分數較不穩
5 常用折衷
10 穩，但成本高

代價：成本變成 K 倍（見成本公式）。

5.2 回報遞減

實測（示範 ②）：同一次搜尋中，「已試候選數」與「目前最佳 CV 分數」的關係

         已試候選數        目前最佳 CV R²        本次提升
             1            0.3076      0.3076
             5            0.5541      0.2465
            10            0.5665      0.0123
            20            0.5665      0.0000
            40            0.5665      0.0000
            80            0.5687      0.0022

讀法： - 第 1→5 個候選：+0.2465（找到「大方向」） - 第 5→80 個候選：只再 +0.0146（16 倍預算換來零點幾）

原理：搜尋的回報是遞減的。前 20% 的預算拿到大部分改進。

5.3 CV 選擇偏誤（本課最反直覺的一段）

現象：搜尋越久，CV 分數越好看，但測試分數不一定跟著好。

實測（示範 ③）：用一份完全沒有訊號的資料（隨機標籤，真實準確率必然是 0.5）

     候選數       最佳CV準確率       測試準確率      樂觀差距
      10        0.5733      0.5500    0.0233
      50        0.5933      0.5033    0.0900
     200        0.6144      0.5033    0.1111

這張表要讀三件事：

觀察 含義
候選數 200 時，CV 報 0.6144 明明沒有訊號，CV 卻說「有 61% 準確率」
同一組候選的測試準確率只有 0.5033 真實表現＝亂猜（0.5）
樂觀差距從 +0.0233 成長到 +0.1111 搜尋越久，CV 越樂觀

為什麼會這樣：CV 分數是「幾百個候選裡挑最大的」。 挑最大值這個動作本身就會選到「運氣好」的候選——這是統計必然，不是程式 bug。

5.4 對策（三條，全部與搜尋無關）

對策 說明
保留封存的測試集 從頭到尾不參與任何搜尋決策
報告測試分數，不報告 CV 分數 CV 是「用來選」的，不是「用來報」的
預算與資料量匹配 小資料不要大搜尋（會把 CV 擬合掉）

一句話記住：CV 分數是拿來「選」的，不是拿來「信」的。

七、原理 IV｜主要指標決定搜尋方向（15 分）

7.1 搜尋目標 = 你設的主要指標

搜尋演算法只做一件事：把主要指標最大化。所以：

你設什麼指標，它就往那個方向優化——包括你沒想到的副作用。

你設的指標 它會優化出什麼 可能的副作用
準確率 整體猜對比例 在不平衡資料上會忽略少數類
ROC-AUC 排序能力 可能選出較複雜的模型
負 MSE（迴歸） 大誤差被放大 對離群值極度敏感
準確率（迴歸） R² 或負 RMSE 依工具而定，要先確認預設值

7.2 預設值陷阱

多數工具都有預設主要指標（例如分類預設 ROC-AUC、迴歸預設負 MSE）。 若你沒改，就是在用「工具作者的偏好」搜尋，而不是「你的業務需求」。

實務檢查清單： 1. 我知道這個工具現在用的是哪個主要指標嗎？ 2. 這個指標對應我的業務成本結構嗎？ 3. 如果換成另一個指標，選出來的模型會不一樣嗎？

7.3 多目標的可能性

當「分數」與「複雜度」都重要時，有些工具支援多目標優選（見第 6 課）。 若工具不支援，退而求其次的做法是：

  1. 用分數搜尋；
  2. 從前幾名中，手動挑最簡單的那一條。

  4. 因為 CV 分數是「在幾百個候選裡取最大值」。取最大值會選到「運氣好」的候選， 造成系統性高估。資料沒有訊號時，這個高估最容易被看見（真實值 0.5，CV 卻 0.61）。
  5. 搜尋會往「全部猜多數類」的方向優化——因為那樣準確率最高（97%）。 結果會得到一個對少數類毫無辨識力的模型。應改用 ROC-AUC／Recall 當主要指標。

三、原理 I｜搜尋的對象：從「參數向量」到「管線樹」（45 分）

3.1 傳統超參數搜尋的假設

傳統做法先固定結構，再調參數：

結構（人決定）：StandardScaler → RandomForest
參數（機器找）：n_estimators, max_depth, min_samples_leaf …

問題：結構一旦選錯，參數再怎麼調都在同一個天花板下。

3.2 TPOT 的做法：把「結構」也變成搜尋變數

TPOT 把一整條管線表示成樹：

                    最終估計器（分類器／迴歸器）
                            ▲
                  ┌─────────┴─────────┐
            特徵處理分支 A        特徵處理分支 B      ← 可以並聯（特徵融合）
                  ▲                   ▲
            預處理步驟 1          預處理步驟 2
                  ▲
            原始特徵

關鍵差別：

項目 傳統調參 TPOT
搜尋變數 參數值 結構 ＋ 參數值
搜尋空間大小 十萬～千萬 天文數字
人為偏誤 高（結構是人選的） 低（結構由搜尋決定）
可檢視性 高（結構本來就簡單） 需要工具才能看清（見 3.4）

3.3 為何「結構空間」遠大於「參數空間」

一個結構由「節點種類 × 排列 × 深度」決定： - 可選的預處理算子有幾十種 - 排列順序是變數 - 分支可以並聯、可以嵌套 → 結構的數量是組合爆炸的超集合。這也解釋了為何需要啟發式搜尋（L5 的結論在此落地）。

3.4 白盒 vs 黑盒（本課的價值主張）

  • 黑盒 AutoML：只給你「最佳模型物件」，你不知道它長什麼樣。
  • 白盒 AutoML：管線是可檢視的物件，每一步都看得見。

為什麼白盒重要（三點，屬原理而非工具）： 1. 可解釋：能向利害關係人說明「模型做了什麼」。 2. 可交付：管線可以脫離搜尋工具獨立存在（原理：交付的是結構，不是工具）。 3. 可維護：資料或業務改變時，知道該動哪一步。

一句話記住：黑盒給你分數，白盒給你控制權。

3.5 什麼是「搜尋空間」檔次

因為結構空間太大，實務上會提供預設的空間檔次（從極簡到完整）。 - 檔次越簡潔 → 每單位預算能評估的結構越多（但可能找不到複雜解） - 檔次越完整 → 可能找到更強結構（但每條評估更貴）

原理：這是在「搜尋廣度」與「單次評估成本」之間取捨。 （具體檔次名稱與參數見附錄 D。）

四、原理 II｜演化的四個機制（15 分）

4.1 四個機制

機制 生物比喻 在管線上的對應
個體 一隻馬 一條完整管線
族群 一群馬 一組管線（同時評估）
適應度 跑得多快 交叉驗證分數
選擇 淘汰慢的 分數高的有更高機率留下
交叉 交配 交換兩條管線的子樹
突變 基因突變 換算子、改參數、加／減節點
精英保留 冠軍直接晉級 每代最好的個體無條件保留

4.2 為何演化「有效」（這才是重點）

不是因為它神奇，而是因為它做了兩件隨機搜尋做不到的事：

  1. 累積改進：好的子結構會被保留並重組，而不是每次從零開始。 → 隨機搜尋是「重新抽籤」，演化是「在好牌上繼續改」。
  2. 探索與利用的平衡：突變負責探索新結構，交叉負責利用既有好結構。

4.3 選擇壓力：太強與太弱都不行

選擇壓力 後果 現象
太大 早熟收斂 族群很快全長一樣，停止探索，卡在局部最佳
太小 不收斂 跑了很久還在亂試，浪費預算

對應到參數：族群大小（多樣性）與世代數（改進次數）的配比。 → 原理：族群太小 + 世代太多 = 早熟；族群很大 + 世代很少 = 來不及改進。

4.4 多目標優選（進階但重要）

只有一個目標（分數）時，演化會不斷增加複雜度來擠出小數點後的差異。 所以現代實作會做多目標優選：同時優化 - 目標 1：分數越高越好 - 目標 2：模型越簡單越好（節點越少、越易解釋）

結果是一條 Pareto 前緣：多個「互不支配」的候選，由人來選。

一句話記住：當分數打成平手時，讓複雜度決定勝負。

五、原理 III｜預算與收斂（30 分）

5.1 預算三要素

總成本 ≈ 族群大小 × 世代數 × 折數 × 單條管線訓練成本
要素 增加它會怎樣
族群大小 每代更多樣，但每代更慢
世代數 更多改進機會，但邊際效益遞減
折數（CV） 分數更穩，但成本線性上升
資料量 最大的隱形乘數（每條管線都要在全資料上做 K 折）

實務觀察：真正的瓶頸是「要評估很多條管線 × 每條都要 K 折」，不是訓練單一模型。 所以資料量一大，成本是相乘上升的。（實測對照見附錄 E-3。）

5.3 CV 選擇偏誤（最容易被忽略的陷阱）

現象：搜尋越久，CV 分數越好看，但測試集分數不一定跟著好。

原因： 1. 你是在同一個 CV 分數上做「取最大值」的操作（幾千條管線中挑最好的）。 2. 取最大值會挑到「運氣好」的候選 → CV 分數被系統性高估。 3. 搜尋越久，這個樂觀偏誤越大。

對策（原理層，不是技巧層）： - 永遠保留一個搜尋過程完全沒看過的測試集。 - 報告時報測試集分數，不報 CV 分數。 - 搜尋預算與資料量要匹配：小資料不需要大預算（會過擬合 CV）。

時間預算 時間可控（適合有時間上限／SLA 的場合），但改進次數不可預期

七、原理 IV｜兩條哲學路線的取捨（25 分）

7.1 兩條路線

路線一：演化搜尋單一最佳管線 路線二：廣搜多模型再集成
策略 深挖結構空間，找一條最好的 廣撒網，把多個模型堆疊集成
產出 一條透明的管線 一組模型 ＋ 一個集成器
優點 可檢視、可交付、可維護 通常分數更高、更穩
缺點 分數可能不是最高 較難解釋、較難交付

7.2 選型判準（原理層）

需要「說得清楚模型做了什麼」嗎？
 ├─ 是 → 路線一（透明管線）
 └─ 否 → 分數是唯一目標嗎？
          ├─ 是 → 路線二（廣搜＋集成）
          └─ 否 → 兩條都跑，用時間預算控制成本再比較

7.3 白盒管線的交付價值（三個層次）

  1. 技術交付：管線可以脫離搜尋工具獨立存在 → 部署環境不需要安裝搜尋工具。
  2. 組織交付：非技術利害關係人能看懂步驟 → 建立信任。
  3. 時間交付：半年後回來維護，還知道每一步為什麼在那裡。

一句話記住：搜尋工具是過程，管線才是產品。

7.4 常見誤解

誤解 正確理解
「演化一定比隨機搜尋好」 小預算下兩者差不多；演化優勢來自「累積改進」需要足夠世代
「世代數越多越好」 回報遞減＋CV 選擇偏誤；超過高原後只是浪費預算
「找到最佳管線就結束了」 還要看結構是否冗餘、是否可解釋、是否能交付
「分數高就是好模型」 分數相同時選簡單的；分數不同時還要看泛化（測試集）

三、原理 I｜偏差與變異數（40 分）

3.1 誤差的兩個來源

模型誤差可以拆成兩部分：

來源 意思 症狀
偏差（Bias） 模型的假設太簡單，學不到真實規律 訓練與測試都差（欠擬合）
變異數（Variance） 模型對訓練資料太敏感，換一批資料結果就變 訓練好、測試差（過擬合）

3.2 集成的兩個攻擊點

手法 攻擊 做法
Bagging 降低變異數 同一模型、不同資料子集／特徵子集，訓練多個後平均
Boosting 降低偏差 串接多個弱模型，每個專注修正前一個的殘差
Stacking 兩者兼顧 用多個異質模型當第一層，再用一個模型學習如何組合

一句話記住：集成不是「多跑幾次取平均」，是「針對誤差來源下藥」。

3.3 為什麼「平均」能降低變異數

若多個模型的誤差彼此獨立，平均後誤差的變異數會下降（平均 N 個獨立誤差，變異數約降為 1/N）。 實務上模型之間有相關性，所以效果打折——但仍然有效。

Ridge 的分數（0.6465）比所有集成都高，而且標準差是 0。

這說明什麼：這份資料的真實關係接近線性，所以「正確的簡單模型」勝過所有集成。 集成不是萬靈丹——它只是在「你的模型不對」時，幫你少錯一點。

一句話記住：先用簡單模型確認基線，再考慮集成。

5.3 實測輸出 ②：排行榜的排名會跳

  模型                 切分0       切分1       切分2       切分3       切分4        平均      排名變化

面向 想要更多 → 要付出什麼

八、自我檢核（理解題）

先自己寫答案，再看下一節的對照。

# 題目 對應原理
1 用「偏差－變異數」解釋 Bagging 與 Boosting 各自在攻擊什麼。 原理 I
2 示範中 Ridge 的分數（0.6465）比所有集成都高。這說明了什麼？ 原理 I
3 為什麼 Bagging 的標準差（0.0090）比單一深樹（0.0265）小？ 原理 I
4 隨機森林平均 0.5681、Boosting 平均 0.5626，排名在 2~3 之間跳。你該怎麼選？ 原理 III
5 「提升幅度必須大於分數的變動幅度」——請用示範中的數字說明這句話。 原理 IV

答案與解說

  1. Bagging 攻擊變異數：多個模型平行訓練後平均，把「對資料敏感」的部分平均掉。 Boosting 攻擊偏差：串接弱模型，每個專注修正前一個的殘差，逐步逼近真實規律。
  2. 說明這份資料的真實關係接近線性，「正確的簡單模型」勝過所有集成。 集成不是萬靈藥——它只在「模型選得不對」時幫你少錯一點。 實務含義：先建立簡單基線，再考慮集成。
  3. 因為平均多個模型會把「單一模型對資料的敏感度」抵銷掉。 理論上若誤差獨立，平均 N 個模型可把變異數降到約 1/N；實務上有相關性，所以效果打折但仍有感。
  4. 兩者差距（0.0055）小於分數的變動幅度（標準差 0.001~0.026 量級、排名會跳）， 所以視為同級。此時應該改用其他判準：可解釋性、訓練時間、部署難度、維護成本。
  5. 單一深樹的測試分數標準差是 0.0265，代表「換個隨機種子，分數就會上下跳 ±0.026」。 所以任何小於約 0.026 的「提升」都可能只是運氣，不能當作真的進步。

十、自學提醒與常見卡點

  • 不要相信單一次的分數。任何模型比較都應該看「平均 ± 變異」。
  • 集成不是「越多模型越好」：模型之間的相關性越低，平均的效果越好。
  • Boosting 對雜訊敏感：資料標籤品質差時，它會認真去學雜訊。
  • 排行榜（Leaderboard）只是當下這組切分的結果，不是客觀真理。
  • 本課刻意用「換隨機種子」來製造分數變異——這在真實專案裡也一樣會發生， 只是你不會每次都注意到。

三、原理 I｜雲端賣什麼（40 分）

3.1 三個真實的產品

賣點 具體是什麼 本機做不到的地方
算力彈性 用完就關的機器、可平行擴展 你的電腦只有那麼多核心
治理與審計 誰跑了什麼、用什麼資料、產出什麼，全程留痕 本機沒有強制留痕機制
生命週期（MLOps） 版本管理、部署、監控、重訓的整合流程 本機要自己拼裝

關鍵：雲端不保證演算法更好。它的價值在工程與治理，不在模型。

3.2 為什麼企業願意付錢

企業痛點 雲端怎麼解
「這個模型是誰訓練的？用哪版資料？」 作業與資料資產都有版本與稽核紀錄
「換人接手就沒人懂了」 流程標準化、資產集中管理
「臨時要跑大規模實驗」 開機器、跑完、關機器
「合規要求要能舉證」 存取控制與日誌

3.3 反過來：什麼情況雲端不划算

  • 資料極小、實驗時間以秒計 → 本機更快（沒有上傳下載與排隊）
  • 資料不能出本地（法規或商業機密） → 只能本機或私有部署
  • 只需要一次性分析 → 雲端的治理成本不划算

一句話記住：雲端買的是「可治理的算力」，不是「更好的模型」。

七、原理 IV｜資料主權、合規與上雲五判準（20 分）

7.1 上雲的五個判準

# 判準 偏向本機 偏向雲端
1 資料量 小（< 10 萬筆） 大（百萬筆以上）
2 算力需求 單機跑得完 需要多機平行
3 合規要求 資料不能出本地 需要審計留痕

判準的用法：把五項打勾，看哪邊多。不要只憑「雲端聽起來比較專業」決定。

7.2 資料主權的三個層次

層次 意思 實務影響
資料存放地 資料實際存在哪個國家／區域 法規可能要求留在境內

常見誤解：「上雲＝資料不安全」。 實情是：雲端的技術安全通常比本機好，但資料主權是法律問題，不是技術問題。

7.3 混合模式（實務最常見）

敏感資料留在本機 → 去識別化後上傳 → 雲端訓練 → 模型下載回本機部署

這個模式同時取得「合規」與「算力」，是多數企業的實際做法。

一句話記住：先問「資料能不能出去」，再問「算力夠不夠」。

  5. 混合模式：敏感資料留在本機（或本地私有環境）完成前處理與去識別化， 只把去識別化後的資料上傳訓練，模型訓練完下載回本機部署。 若連去識別化都不允許，就只能在本機或私有雲內解決算力。

三、原理 I｜解釋＝擾動＋觀察（35 分）

3.1 所有解釋方法的共同骨架

不管叫 SHAP、Permutation、PDP 還是 ICE，本質都是同一個動作：

① 取得基準分數
② 對某個東西「做一點擾動」（打亂它、改變它、移除它）
③ 看分數掉了多少
④ 掉得多 = 模型依賴它；掉得少 = 模型不依賴它
方法 擾動什麼 觀察範圍
Permutation importance 打亂某一欄的值 全域
SHAP 移除某個特徵的貢獻（用賽局理論分配） 全域 ＋ 單筆
PDP 把某欄固定在某一系列值 全域（看趨勢）
ICE 同上，但每一筆畫一條線 單筆（看異質性）
誤差分析 不看特徵，改看「哪些樣本錯最兇」 個案

3.2 一個關鍵區別

解釋方法說明的是「模型怎麼想」，不是「世界怎麼運作」。

模型可能因為某個特徵與目標相關而依賴它，即使它們之間沒有因果關係。 這一點是下一節的主題。

3.3 為什麼需要解釋

需求方 想知道的
業務方 「為什麼這個客戶被拒絕？」
稽核／法規 「你的決策依據是什麼？可重現嗎？」
開發者 「模型是不是在偷看某個不該看的欄位？」
資料方 「是不是某個欄位品質變差了？」

一句話記住：不能解釋的模型，不能上線。

四、原理 II｜重要性沒有唯一答案（20 分）

4.1 兩種常見定義，測不同的東西

定義 怎麼算 偏好 適合問的問題
不純度重要性（樹內建） 統計「分裂時用得多不多」 偏愛高基數／連續欄位 「模型內部用到它嗎？」
置換重要性 打亂它，看分數掉多少 貼近實際依賴 「失去它會多差？」

兩者會給出不同排名——這不是 bug，是因為它們在問不同的問題。

4.2 共線性會「分攤」重要性

當兩個欄位高度相關時：

  • 不純度重要性會隨機偏向其中一個（先被選中的那個拿到大部分分數）
  • 置換重要性會兩者都很低（因為打亂其中一個，另一個還可以提供同樣的資訊）

實務含義：看到「兩個高度相關的欄位，其中一個重要性很高、另一個很低」， 不要直接說「前者重要」——先檢查它們的相關性。

4.3 相關不等於因果（本課最重要的警告）

情況 例子 危險
特徵是結果而非原因 「已結案」欄位 這是洩漏（見第 4 課）
特徵是代理變數 郵遞區號 → 種族 造成間接歧視
特徵只是同期相關 「今天下雨」與「今天塞車」 模型學到的是巧合

一句話記住：重要性高只代表「模型依賴它」，不代表「它造成結果」。

五、原理 III｜漂移＝分佈的統計檢定（35 分）

5.1 兩種漂移

類型 什麼變了 影響
資料漂移（Data drift） 輸入特徵的分佈變了 模型可能仍有效（若關係沒變）
概念漂移（Concept drift） 特徵與目標的關係變了 模型一定失效

診斷順序：先看資料漂移（容易監控），再用效能指標確認是否真的變差。

5.2 PSI：把漂移變成一個數字

PSI（Population Stability Index） 的做法：

① 用「基準資料」切出分位數區間（例如 10 等分）
② 數一數「目標資料」落在各區間的比例
③ 比較兩組比例，算出一個綜合差異分數

慣用閾值：

PSI 判定 行動
< 0.10 穩定 不用處理
0.10 ~ 0.25 中度移動 開始觀察，檢查是否影響效能
> 0.25 明顯漂移 該處理（重訓／換特徵）

5.3 PSI 的三個實務限制

限制 說明
需要足夠樣本 樣本太小時，抽樣噪音會蓋過真實漂移（本課示範有實測）
對二元／類別欄位不敏感 分位數切點會退化，建議改用比例差異
漂移 ≠ 變差 PSI 高只說「分佈變了」，不代表模型表現下降

一句話記住：漂移是「分佈的移動」，不是「模型的失敗」。

六、最小示範（45 分）

目的：把「擾動」「兩種重要性定義」「PSI」三段都量出來。 程式：C:\ml\automl\demos\L09_explain_drift_demo.py 環境建置見附錄 A；跑不動或報錯，先用原始錯誤訊息查附錄 B。

6.1 實測輸出 ①：擾動＋觀察

資料設計：x1_真因（真正有用的主因）、x2_與x1共線（高度相關）、 x3_純雜訊、x4_二元雜訊。

  模型原始測試 R² = 0.8697

  欄位                  打亂後 R²         掉多少
  x1_真因              -1.0615      1.9312
  x2_與x1共線            0.8632      0.0066
  x3_純雜訊              0.8766     -0.0069
  x4_二元雜訊             0.8665      0.0033

讀法： - 打亂 x1 → R² 從 0.8697 掉到 -1.0615（掉 1.93）→ 模型高度依賴它。 - 打亂其他三個 → 幾乎不變（甚至微升，因為打亂等於加雜訊）。 - 注意 x2：它與 x1 高度相關，但打亂它幾乎沒影響 → 因為 x1 還在。

這證明：擾動＋觀察能告訴你「模型依賴誰」，但無法告訴你「誰是原因」。

6.2 實測輸出 ②：同一棵樹，兩種重要性，兩個排名

  欄位                      樹內建（不純度）         置換重要性
  x1_真因                     0.9173        1.6470
  x2_與x1共線                  0.0491        0.0053
  x3_純雜訊                    0.0287       -0.0008
  x4_二元雜訊                   0.0049        0.0016

  樹內建排名：x1_真因 > x2_與x1共線 > x3_純雜訊 > x4_二元雜訊
  置換排名　：x1_真因 > x2_與x1共線 > x4_二元雜訊 > x3_純雜訊

看第 3、4 名：兩種定義交換了排名（x3 與 x4）。

為什麼： - 不純度偏愛連續／高基數欄位 → x3（連續）排前面 - 置換看實際依賴 → x4（二元）排前面

這證明：「特徵重要性」沒有唯一答案。報告時必須說明用的是哪一種定義。

6.3 實測輸出 ③：PSI 漂移偵測

  基準資料 5000 筆、目標資料 5000 筆
  ⚠️ PSI 需要足夠樣本：樣本太小時，抽樣噪音會蓋過真實漂移。

  欄位                   PSI   判定（慣用閾值）
  f1_幾乎沒動           0.0071   穩定（< 0.10）
  f2_明顯移動           0.5985   明顯漂移（> 0.25）→ 該處理
  f3_輕微移動           0.0839   穩定（< 0.10）
  f4_二元特徵           0.2470   中度移動（0.10 ~ 0.25）→ 要開始看

讀法： - f2（位移 0.8）→ 0.5985，正確抓到「明顯漂移」。 - f1（位移 0.05）→ 0.0071，正確判為穩定。 - f3（位移 0.3）→ 0.0839，判為「穩定」→ 這是 PSI 的敏感度限制： 0.3 個標準差的位移在這個資料量下仍不足以觸發閾值。

6.4 一個必須記錄的實測坑（樣本數）

本課實測：把基準與目標各設為 300 筆、完全不做任何位移， PSI 卻可能高達 0.09 ~ 0.15——足以誤判為「中度漂移」。

結論：PSI 需要足夠樣本。 小樣本下請降低閾值敏感度、或改用其他檢定（如 KS 檢定）、或累積更長時間再判斷。

七、原理 IV｜公平性的定義衝突與負責任 AI（15 分）

7.1 公平性沒有單一定義（這是數學結論，不是立場問題）

定義 要求 直覺
人口統計均等 各族群的「通過率」相同 結果一樣多
機會均等 各族群的「真陽性率」相同 該過的都過
預測均等 各族群的「精確率」相同 預測準度一樣
個人公平 相似的個人得到相似對待 個案一致

重要結論：當各族群的基礎比率不同時， 這些定義在數學上不可能同時滿足。 所以「公平」不是技術問題，而是價值選擇——必須由人決定要犧牲哪一個。

7.2 負責任 AI 六原則的實務含義

原則 實務上做什麼
公平 分群評估指標，而不只看整體
可靠與安全 壓測、邊界案例測試、失敗時的行為設計
隱私與安全 資料最小化、去識別化、存取控制
包容 確認服務對象都能使用（無障礙、語言）
透明 提供解釋、記錄決策依據
問責 出事時知道找誰、有沒有人工複核機制

7.3 三個可落地的檢查

  1. 分群評估：把測試集按敏感特徵分組，分別算指標（不要只看整體平均）。
  2. 人工複核邊界：分數落在「模糊地帶」的案例，交給人決定。
  3. 留痕：記錄每次預測的輸入、輸出、模型版本——出事時才查得出來。

一句話記住：準確的模型，也可能是不可接受的模型。

# 題目 對應原理

答案與解說

三、原理 I｜三道鴻溝（35 分）

3.1 鴻溝一：環境可重現性

症狀 原因
「在我的電腦上跑得動，在別人的跑不動」 環境沒有鎖定（套件版本、系統差異）
「三個月後重跑，結果不一樣」 沒有固定隨機種子、資料已更新

跨越方法：環境快照（見附錄 A-2）＋ 固定隨機種子 ＋ 資料版本標記。

3.2 鴻溝二：資料分佈改變

症狀 原因
離線分數好、上線就變差 上線後的資料分佈與訓練時不同
分數慢慢下滑 漂移累積（見第 9 課）

跨越方法：時間切分驗證（第 4 課）＋ 漂移監控（第 9 課）＋ 定期重訓。

3.3 鴻溝三：監控缺失

症狀 原因
出事了沒人知道 沒有監控指標與告警
知道變差了但不知道為什麼 沒有留痕（輸入、輸出、模型版本）

跨越方法：上線前就定義「要看什麼、超過多少要告警、告警後做什麼」。

3.4 三道鴻溝的共同點

它們都不是「模型」的問題，而是「工程與流程」的問題。

這解釋了一個常見現象：很多專案不是敗在模型不好，而是敗在交付不出去。

一句話記住：實驗的終點不是「分數好」，而是「能被信任地使用」。

四、原理 II｜可重現性三要素（20 分）

4.1 三要素

要素 要求 檢查方式
程式 從原始資料到模型，全流程可執行 換一台乾淨的機器，照文件跑一次
資料 有版本、有來源、有切分規則 能回答「這個模型用的是哪一版資料」
環境 套件版本已鎖定 有環境快照或鎖定檔

判斷標準：換一個人、換一台機器、隔三個月，能不能得到相同的結果？ 能 → 可重現；不能 → 這不是「交付」，只是「展示」。

4.2 可重現性的三個實作習慣

  1. 固定隨機種子：任何涉及隨機的步驟都要設種子（搜尋、切分、模型初始化）。
  2. 環境快照：匯出鎖定檔，並記錄關鍵套件版本（見附錄 A-2）。
  3. 資料版本標記：在報告與檔名中標明資料版本與日期。

4.3 一個常被忽略的細節

「隨機」也是可重現性的一部分。 同一個流程跑兩次得到不同分數，不是「模型不穩」，而是你沒有控制隨機源。 （第 7 課的示範就是在量這個變異。）

五、原理 III｜模型是會衰減的資產（35 分）

5.1 為什麼模型會衰減

衰減來源 機制 對應第幾課
資料漂移 輸入分佈改變 第 9 課
概念漂移 特徵與目標的關係改變 第 9 課
業務規則改變 例如促銷策略、產品線調整 —
外部環境改變 例如景氣、競爭對手 —

關鍵心態：模型不是「做完就結束的專案」，而是「需要維護的資產」。

5.2 監控什麼（三層）

層次 監控什麼 多久看一次
輸入層 特徵分佈（PSI）、缺失率、極端值比例 每日／每週
輸出層 預測分佈（例如通過率是否突然改變） 每日
效果層 真實績效（需要等到標籤回流） 每月／每季

為什麼要三層：效果層最準，但最慢（要等結果）。 輸入層最快，可以當早期警報。

5.3 重訓的四個觸發條件

# 觸發條件 說明
1 效果層指標低於門檻 最直接，但要等標籤
2 輸入層漂移超過閾值 早期警報（PSI > 0.25）
3 固定週期 例如每季一次（保守做法）
4 業務事件 例如新產品上線、規則改變

實務建議：2 ＋ 3 併用（漂移觸發 ＋ 定期重訓），1 作為最終確認。

5.4 重訓不是萬靈丹

情況 重訓有用嗎
資料漂移，關係沒變 ✅ 有用
概念漂移（關係變了） ⚠️ 需要重新思考特徵與問題定義
標籤品質變差 ❌ 重訓只會學到壞標籤
業務規則改變 ❌ 需要改的是規則，不是模型

一句話記住：先診斷「哪裡變了」，再決定要不要重訓。

八、自我檢核（理解題）

先自己寫答案，再看下一節的對照。

# 題目 對應原理
1 說出實驗與生產之間的三道鴻溝，並指出它們的共同點。 原理 I
2 用一句話說明「可重現性」的判斷標準。 原理 II
3 為什麼監控要分「輸入層／輸出層／效果層」三層？ 原理 III
4 什麼情況下「重訓」是錯的對策？請舉兩例。 原理 III
5 用四格框架，說明「資料洩漏」應該被放在哪一格。 原理 IV

答案與解說

  1. 環境可重現性、資料分佈改變、監控缺失。 共同點：它們都不是模型的問題，而是工程與流程的問題。 這也是為什麼很多專案「模型不差卻交付不出去」。
  2. 換一個人、換一台機器、隔三個月，能不能得到相同結果？ 能 → 可重現；不能 → 只是展示。
  3. 因為三層的速度與準確度不同： 輸入層最快（可當早期警報）、輸出層次之、效果層最準但最慢（要等標籤回流）。 三層並用才能在「太早誤報」與「太晚發現」之間取得平衡。
  4. 例：(a) 標籤品質變差時——重訓只會學到壞標籤，要先修標籤； (b) 業務規則改變時——要改的是規則，不是模型。 另外概念漂移時單純重訓也通常不夠，需要重新思考特徵與問題定義。
  5. 發生機率高、影響大 → 必須現在處理。 （它會讓離線分數虛高、上線失敗，且幾乎每個專案都可能踩到。）

九、練習（本課的練習就是綜合演練）

  1. 用第六節的 11 個步驟，對你手上的資料做一次完整演練，產出一頁式報告。
  2. 把報告給一個不懂 ML 的同事看，請他回答三個問題： ① 這個模型要解決什麼？② 它有多好？③ 什麼時候會變差？ 若他答不出來，請修改報告——這就是「可交付」的真正標準。

十、自學提醒與常見卡點

  • 本課沒有程式，是刻意的：生產階段的問題幾乎都不是程式問題。
  • 最容易忽略的是「分數的變動幅度」。報告「提升了 0.01」之前， 先確認變動幅度是不是比 0.01 還大（第 7 課）。
  • 不要等到上線才想監控。上線前就要定義「看什麼、多少要告警、告警後做什麼」。
  • 交付檢查清單請實際跑一次（換機器），不要只在腦裡確認。

C-1 主體為什麼不寫版本

公約：主體（大綱、各課）不寫版本號與 API 名稱。

理由： 1. 寫了會過期 → 教材跟著版本一起爛。 2. 版本差異不影響原理：殘差還是殘差、演化還是演化。 3. 要學的是「遇到 API 變了怎麼辦」，而不是背住某個版本的名字。

主體遇到版本問題時的正確寫法：

「找到的管線是白盒物件，可轉成獨立程式碼交付（工具與步驟見附錄 D-4；版本斷點見附錄 C-2）。」

變化類型 舊寫法 新寫法 舊寫法的實際結果
