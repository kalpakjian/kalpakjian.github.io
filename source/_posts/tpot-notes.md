## 重點：講義的程式碼，在 TPOT 1.1.0 上有三行會直接壞掉

這是這份筆記最有價值的部分——**每一則錯誤訊息都是本機實際跑出來的**：

| 講義（0.x 寫法） | 本機實測（1.1.0） | 真實錯誤訊息 |
|---|---|---|
| `TPOTClassifier(verbosity=2)` | `verbose=2` | `TypeError: TPOTEstimator.__init__() got an unexpected keyword argument 'verbosity'` |
| `tpot.score(X_test, y_test)` | `accuracy_score(y_test, tpot.predict(X_test))` | `AttributeError: 'TPOTClassifier' object has no attribute 'score'. Did you mean: 'scorers'?` |
| `tpot.export('pipeline.py')` | `joblib.dump(tpot.fitted_pipeline_, ...)` | `AttributeError: module 'tpot' has no attribute 'export'` |

還有一個連教學文都不會提的坑：**TPOT 在本機（Windows）預設會開 dask 子行程，直接跑會失敗**——

```
RuntimeError: Nanny failed to start.
```

解法是在 `TPOTClassifier(...)` 加上 `processes=False`（改用同一個行程內的執行緒）。而且因為 dask 用 multiprocessing「spawn」開子行程時會**重新 import 主程式**，腳本一定要包在 `if __name__ == "__main__":` 裡，否則**整份程式會被跑兩遍**（本機實測真的發生，我的實驗日誌因此出現兩份輸出）。

## 實測數字：課堂版設定在本機跑多久、幾分？

用講義的參數（`generations=5, population_size=20`，約 100 個模型）在本機跑鳶尾花分類
（Python 3.11.16 / **TPOT 1.1.0** / scikit-learn 1.9.1）：

| 項目 | 實測值 |
|---|---|
| 搜尋耗時 | **約 51 秒**（多次實測 45.6～51.7 秒） |
| 測試集準確率 | **0.9474**（36/38 題） |
| 內部交叉驗證最佳分數 | **0.9822** |
| 最佳管線 | `Normalizer(l1) → SelectPercentile(≈87%) → FeatureUnion ×2 → LogisticRegression(elasticnet)` |

三個值得記下來的觀察：

1. **內部 CV 0.9822 vs 測試集 0.9474**：那是「在 100 條裡挑最好的」的分數，天生樂觀（贏家詛咒）。
2. **最後選的不是隨機森林**：講義舉例說它會試隨機森林／決策樹，但這份資料上它挑的是**邏輯迴歸＋前處理**——TPOT 只在意分數。
3. **測試集只有 38 筆**：錯 1 題就掉 2.6%。講義範例的 0.973 與本機的 0.9474 **只差一題**，不要把單一分數當成絕對值。

另外附錄 D 收錄了**完整可重跑的實測腳本全文與原始輸出**，包含那幾則錯誤訊息的完整 traceback。
