> 這篇是一段技術論辯的**導讀**，不是逐字轉載。原始對話的立場很衝，
> 但拆開來看，它其實是三個層次的論證疊在一起：**我實戰驗證過 → 架構已經換代 → 成本論本身搞錯了重點**。
>
> 我把這三層分開講清楚，順便把「稠密融合」「冗餘訓練」「稀疏 token」「端到端」這些名詞攤平解釋。
> 中段會標出我認為**論述上不夠扎實**的三個地方——那段話說服力很強，但不代表每個推論都成立。
>
> **然後拉到下一層看。** 上面那些「以前很難、現在不難」的變化，其實都有同一個底層原因：
> 訓練資料的產生方式變了。所以文章後半（第六到九節）會接著講我自己的一套說法——
> **World Model War 1（WMW1）**：接下來的主戰場是 on-policy RL ＋ 世界模型，
> 而 2026 年 10 月那場「ETH 被 AI 證偽」的事件，正好是這場戰爭的第一聲炮響。
> （順帶把一個常見的誤解修掉：被推翻的是 ETH，不是 P≠NP。）

## 一、先看那場論辯到底在吵什麼

有人在質疑「LiDAR 與 camera 融合」這條路線：難做、不相容、成本高，不如走純視覺。

反方的回應結構，大致是這樣：

1. **這不是紙上談兵**——三年前就在真實城區道路上跑過 LiDAR + camera 的實車。
2. **那時候難，是因為架構落後**——稠密融合＋硬體不對稱，逼得你必須加冗餘模組與冗餘訓練。
3. **現在架構換代了，問題自動消失**——端到端、稀疏特徵、統一的 token 序列，融合是模型自己學的事。
4. **成本論站不住腳**——光達一顆兩三千人民幣，真正的錢坑是資料與算力的規模競賽，而那正是純視覺路線的成本結構。

換句話說，反方不是在主張「融合比較好」，而是在主張**「融合難／融合貴」這兩個反對理由已經過期了**。這是兩個完全不同的命題，很多爭論是在這裡打歪的。

## 二、舊架構：為什麼當年真的難

### 噸位不對稱的硬體配置

當年的車是這樣裝的：

| 方位 | 感測器 |
|---|---|
| 前向 | LiDAR ＋ camera |
| 後向 | 只有 camera |

這不是設計偷懶，是成本與機構限制下的現實取捨。但它製造了一個很麻煩的性質：**車子前後兩側的「世界模型」不是同一種東西**。前面是世界座標裡有精確深度的一大片點；後面是從 2D 影像反推深度的估計值。

而且那段測試是在**開放城區**跑，不是封閉測試場——有行人、有違停、有突然切進來的機車。封閉場地能靠調參過關的東西，在城區會直接爆掉。

### 稠密融合的代價

**稠密融合（dense fusion）**的典型做法，是把 LiDAR 點雲柵格化成 voxel 或 BEV 特徵圖，把攝影機特徵也投影到同一個網格，然後逐格對齊、拼接、做卷積。

問題在於「稠密」兩個字：

- 一個 100m × 100m × 5m 的空間，用 0.2m 解析度切，就是 **625 萬個格子**。絕大多數格子是空的。
- 你為了讓卷積好算，把空的地方也鋪滿零，等於花大量算力在計算「這裡沒有東西」。
- 兩種模態的特徵分佈差異很大（點雲稀疏且深度準、影像稠密但深度弱），硬拼在一起的表徵很容易被其中一方主導。

### 於是長出 redundancy module 與 redundancy training

因為硬體不對稱、表徵又不一致，當年的解法是**用工程手段補償架構缺陷**：

- **冗餘模組（redundant module）**：針對「前向有兩路、後向只有一路」的落差，額外設計備援分支——某一路失效時，另一路要能撐住辨識能力。等於在網路裡手工刻出「如果 A 掛了就看 B」的邏輯。
- **冗餘訓練（redundant training）**：訓練時隨機把某個模態 dropout 掉（關掉光達、或遮掉某顆鏡頭），逼模型學會在缺感測器的情況下仍能運作。業界常說的 sensor dropout 就是這個手法。

這些不是炫技，是**當年為了上車不得不付的稅**。它讓系統變複雜、訓練變慢、調參變難、而且每個新感測器配置都要重做一輪。

## 三、新架構：為什麼現在這些稅不用繳了

### 端到端把「模組邊界」拆掉了

**端到端（end-to-end）**的意思是：不再有人工切分的「感知 → 預測 → 規劃 → 控制」四段式管線，而是用一個（或一組緊密耦合的）神經網路，從感測器輸入直接算到軌跡與控制量。

這件事的關鍵不在「網路變大」，而在**中間的介面消失了**。以前「感知輸出物件框 → 預測輸出軌跡 → 規劃輸出速度曲線」，每一層的輸出格式都是人訂的，誤差在層與層之間累積，而且每一層的損失函數都跟最終目標脫鉤。端到端之後，梯度可以直接從「這台車開得好不好」回傳到最前面的特徵提取。

### 稀疏特徵：不再為空白空間付錢

**稀疏特徵（sparse features）**是這個轉折的技術核心。它不去鋪滿整張 BEV 圖，而是只保留「有東西命中的位置」或「模型認為值得關注的位置」——文獻裡常見的形式是 query-based 的少量查詢點，或是 sparse voxel / pillar。

好處是雙重的：

1. **算力**：計算量從「跟場景體積成正比」變成「跟場景裡真的有多少物體成正比」。城區再亂，物件數量也有一萬個上限。
2. **對齊**：稀疏表示天生適合當「集合」處理，而集合正是 Transformer 的輸入格式。

### token 化讓「不相容」這個詞失去意義

把 LiDAR 的稀疏特徵與攝影機的特徵都投影成同一維度的向量，就是一串 **token**——跟語言模型把字詞變成向量的做法是同一件事。

於是：

- 兩路感測器的輸出**型態完全相同**（都是 `[N, D]` 的向量序列）；
- 誰對應誰、哪裡該加權，交給 **attention（注意力機制）** 自己學，不需要人工寫投影矩陣與對齊規則；
- 下游的 **decoder** 拿到的是混好的一串 token，直接輸出規劃與控制。

這就是那段話最核心的一句：**「哪有什麼不相容」**。在不同的資料型態層面，確實不相容；但在 token 層面，它們只是同一個序列裡的兩種詞。硬體不對稱（前有後無）也不再是架構問題，而是**訓練資料分佈問題**——模型會自然學到「後方 token 的資訊量比較少」對應的置信度。

### 輸出也搬進 3D

舊系統常見的做法是：在 2D 影像上偵測、再把框投影/反投影到 3D。中間那層投影假設（地面平面、相機內參、深度估計）就是誤差來源。

現在的輸出形式——3D 軌跡、3D 邊界框、**佔用網格（occupancy grid）**——是直接在 3D 空間裡監督的。少了投影這道二手轉換，也就少了一整個誤差類別。

## 四、成本那一段：論點對了一半

原文的價格與規模主張，數字大概是：

| 項目 | 主張 |
|---|---|
| 單顆光達 | 2,000–4,000 人民幣（4,000 已算被貴到） |
| 自家訓練算力 | 約 400 張 GPU |
| 自家訓練資料 | 150–200 萬幀 |
| 對照組訓練算力 | 數十萬張 GPU |
| 對照組訓練資料 | 上億幀 |

這些數字的**方向**是可理解的：中國供應鏈（禾賽、速騰、圖達通等）這幾年把車規光達價格打到消費性電子的量級；而純視覺路線的門檻從來不是「省下感測器的錢」，而是「你得有幾十萬張卡和上億幀資料，才有資格只靠影像」。

所以真正該問的問題不是「要不要花那三千塊」，而是**「你的資料飛輪轉不轉得起來」**。這一層原作者說對了：拿硬體成本當擋箭牌，是把成本結構看反了。

## 五、我認為這段話不夠扎實的三個地方

### 1. 稀疏化不能取代功能安全冗餘

架構上「不需要冗余 module」是對的——因為 token 化之後不需要人工刻備援分支。但 **redundancy 是系統層與法規層的要求**，不是特徵表示的問題。

- **ISO 26262**（功能安全）：要求單點失效（single point fault）不能導致危害。一顆光達被泥巴蓋住、一顆鏡頭被逆光打爆，系統仍然要能達到安全狀態。這需要的是**硬體冗餘、異質冗餘、失效偵測與降級策略**，不是「模型很聰明」。
- **ISO 21448 / SOTIF**（預期功能安全）：處理「系統沒壞，但情境超出設計範圍」的問題。

端到端模型反而讓這件事**更難論證**，因為你很難解釋「為什麼這個 token 序列會導致這個決策」。所以業界在端到端之上還是會掛一層規則化的安全監控（safety monitor / fallback），這本質上就是冗餘。

### 2. 「一顆 2,000–4,000」跟「主光達」不是同一個比較基準

這個價位對應的通常是**補盲（blind-spot）用、低線數、半固態**的光達，規格上跟早期 64 線以上的主光達不是同級。用補盲光達的價格去反駁「主光達成本高」，嚴格說是換了比較對象。

不過話說回來——現在業界主流的確是**「主光達降規 + 多顆補盲」**的打法，這個趨勢本身就支持「成本已經不是門檻」的結論。只是論證過程要誠實。

### 3. 400 卡 vs 幾十萬卡，推不出「成本不是問題」

這兩件事的因果其實是反的。特斯拉的規模優勢是**資料飛輪**，不是「成本高所以該省光達」。它不用 LiDAR 是策略選擇（純視覺 + 海量資料 + 自研晶片），不是財務壓力。

拿自家的 400 卡去對照幾十萬卡，證明的是「我們規模小很多但還是做出來了」，而不是「成本不構成壁壘」。如果要論證後者，該比的是**每萬公里接管次數 vs 每公里資料/算力成本**，那是完全不同的曲線。

### 小結：工程免責 ≠ 安全免責

上面三點可以合成一句：**工程上的簡化，不等於安全上的免責。**
功能安全冗餘、失效降級、可解釋性這三件事，在端到端架構下**反而更難做**，也更需要被認真對待——因為你很難解釋「為什麼這串 token 導致這個決策」。

而這正好是下一節的起點：如果工程門檻降了，那**真正的門檻跑到哪裡去了**？

## 六、把鏡頭拉遠：從「融合是不是問題」到「下一個問題是什麼」

前面六節談的是**單一技術決策**（要不要 LiDAR、怎麼融合），但如果只看到這裡，會漏掉一件更重要的事。

回頭看整條線：稠密融合 → 稀疏 token → 端到端，這三次轉變的共同點不是「模型變大」，而是同一件事：

> **學習訊號的來源，從「人類標註」換成了「環境回饋」。**

- 稠密融合時代：需要人標 3D 框、標佔用、標車道線。人有多快，模型就多快。
- 端到端時代：需要的資料量暴增到 150–200 萬幀起跳，人類標註根本跟不上。
- 那資料從哪來？**兩個地方**：一是在虛擬世界裡大量試錯（世界模型），二是用「對錯」而不是「正解」來訓練（RL）。

這就是我把接下來這段稱為 **WMW1（World Model War 1，世界模型大戰第一回合）** 的原因。

### 為什麼是「戰爭」

因為這是一場**關於訓練資料生產能力的軍備競賽**，而不是模型之間的對打。三個陣營的護城河完全不同：

| 陣營 | 核心資產 | 爭的是什麼 |
|---|---|---|
| **世界模型派**（影片生成、可互動 3D 場景） | 高保真、物理一致的模擬器 | 誰的虛擬世界能當「訓練場」 |
| **RL 基礎設施派** | 海量平行環境 + 便宜的 rollout | 誰的 GPU·小時轉換率最高 |
| **驗證器派**（reward model、形式化驗證、Lean） | 可靠的自動評分 | 誰能把「對錯」定義得又快又準 |

而真正的勝負手是**三者的組合**。理由在後面幾節展開。

## 七、支撐 WMW1 的四個機制（以及三個要修的類比）

下面四點是我整理的理解框架。其中三個用比喻講最快，但**每個比喻都有一個地方會失真**，我一個一個標出來。

### 機制一：多重影分身 —— on-policy RL 的本質是「平行時空的自己」

`on-policy RL`（同策略強化學習）最貼切的比喻，是鳴人第一次學螺旋丸時用多重影分身一起搓：

| 火影 | RL |
|---|---|
| 多重影分身 | **平行環境（parallel envs）**，一次開幾千個 |
| 每個分身各自試 | **rollout**，每個環境跑自己的軌跡 |
| 分身看到的情況都不同 | **探索（exploration）**，不同軌跡覆蓋不同狀態 |
| 分身解除、經驗灌回本體 | **梯度彙總**，算優勢（advantage）後更新同一組參數 |
| 本體變強 | **策略更新（policy update）** |

關鍵在最後兩步「**經驗回本體**」。所有分身用的**都是同一份當下版本的 brain**，收集完立刻更新，舊分身作廢、重新 spawn。這就是 on-policy 的定義：資料必須來自「當前這版策略」。用舊版本產生的資料去訓練，就叫 off-policy——省，但會偏。

> ⚠️ **比喻失真的地方**：鳴人的分身是「已經很會搓」的分身，而 RL 的分身是「同一份尚未學會的 brain 複製幾千份」。所以這不是「找一群專家開會」，而是**「同一個實習生複製幾千份，同時去失敗幾千次」**。

### 機制二：時間被從成本函數裡刪掉了

原文裡最容易被低估的一句是「訓練過程時間是壓縮的，已經發生過的事情可以快速播放」。

在**真實世界**這句話不成立：撞車就是撞車，一天只能跑八小時，物理時間不可壓縮。

但在**世界模型**裡它完全成立：可以超即時（faster-than-realtime）跑、可以隨意重置、可以倒帶、可以刪掉重來、可以把「罕見但致命」的情境密集重播。

所以「AI 一年內學完你幾十年經驗」的真正機制，不是「AI 比較聰明」，而是：

> **人類累積經驗的成本單位是「年」；AI 累積經驗的成本單位是「GPU·小時」。**
> 這兩者之間的匯率，決定了誰快。

**「經驗貶值」的精確版本**應該是：**「可驗證正確與否」的經驗貶值最快，「不可驗證的直覺經驗」反而升值。**
因為前者 RL 可以自己生產幾百萬次，後者（例如「這台車的煞車踏板在某個溫度下的腳感」）模擬不出來，只能靠人。

### 機制三：只需要「對/錯」，不需要「正解」——但門檻換了地方

原文說「你不會開車也能做自動駕駛、不是全知全能的人也在做 LLM」，這是對的。但這裡有一個**極容易被跳過的限定條件**：

**你需要一個能給出「對錯」的東西。** 這東西叫 `reward`（獎勵）或 `reward model`。

| 你以為的門檻 | 實際的門檻 |
|---|---|
| 「你要懂怎麼開車」 | ❌ 不需要 |
| 「你要能定義什麼叫好的駕駛」 | ✅ **需要，而且極難** |

這就是業界最痛的問題：`reward hacking`（獎勵被鑽漏洞）。
你定義「不要撞車」，模型就學會「停在路邊一動不動」——完全符合獎勵，但這不是開車。
你定義「快點到目的地」，模型就學會「逆向行駛」。

> ⚠️ **比喻失真的地方**：「OpenAI 的人不是每個都會設計 IC」這個類比要補一句——**他們有 EDA 工具、有驗證流程、有 tape-out 回饋**。「不會動手」不等於「不知道壞了會怎樣」。

所以更精確的說法是：

> **RL 降低的是「動手能力」的門檻，不是「判斷能力」的門檻。**
> **知識（knowledge）貶值，但判斷標準（criterion）升值。**

在 LLM 上這個區分更明顯：預訓練吃的是「人類寫過的所有東西」（知識），已經快挖光了；RLHF / RLVR 吃的是「人類的偏好與對錯判斷」（判斷），還非常稀缺。**這正是為什麼現在大家搶的是驗證器與標註品質，而不是資料量。**

### 機制四：RL 是「有方向的窮舉」——但別高估這個方向

| | 窮舉（brute force） | RL |
|---|---|---|
| 搜尋空間 | 整個狀態空間，一格不放 | 只往 policy 認為機率高的地方走 |
| 有沒有先驗 | 沒有 | 有（policy 的機率分佈） |
| 樣本效率 | 隨空間大小指數爆炸 | 好很多，但仍然很低 |
| 會不會漏解 | 不會（保證完備） | **會**（policy 可能永遠不去探索正確分支） |

後兩列是關鍵。**方向性帶來效率，也帶來盲區。** 這就是 `exploration-exploitation dilemma`（探索與利用的兩難）：RL 可能收斂到一個「還不錯的錯答案」，而且自己不知道。

「比窮舉少」是對的，但「少到可以忽略」是錯的。實際數字感：LLM 在可驗證獎勵的 RL（RLVR）上做數學題，常常要**同一題採樣幾十到幾百次**才碰到一次正確答案，才有梯度可用——這就是 `pass@k` 曲線在談的事。

> 所以它不是「聰明地少試幾次」，而是**「在極度昂貴的嘗試中，把有效的那些挑出來」**。

## 八、查核：被推翻的是 ETH，不是 P≠NP

這裡插一段**事實修正**，因為原文的類比建立在一個常見的誤解上，而這個誤解會讓整個結論歪掉。

### 2026 年 10 月實際發生的事

| 項目 | 事實 |
|---|---|
| 被推翻的猜想 | **ETH（Exponential Time Hypothesis，指數時間假設）**，連帶 SETH |
| 誰做的 | OpenAI 發表論文 + **Lean 形式化證明**；數小時後 Anthropic 也發表自己的版本 |
| 誰在驗證 | Impagliazzo、Paturi（**1999 年提出 ETH 的本人**）、Ryan Williams、Ryan O'Donnell 組成工作組 |
| 社群態度 | Fortnow：「可以安全假設 ETH 已經被幹掉了」——但**這不是「P=NP 被證明」** |
| 是否動搖密碼學 | OpenAI 科學負責人 Dan Roberts 表示：**沒有** |
| P vs NP | **完全沒有解決**，仍是懸而未決的千禧年難題 |

**ETH 是什麼？** 一句話：3-SAT（最經典的 NP-complete 問題）不可能在 `2^(cn)` 時間內解掉（`c` 為某個正的常數）。也就是「NP 難題本質上就是指數級難」。

OpenAI 給出的演算法，把 `k`-SAT 求解時間壓到：

```text
(n+m)^O(1)  ·  2^O( n · log log n / sqrt(log n) )
```

指數項 `n · log log n / sqrt(log n)` 比 `c·n` 小得多（雖然仍比 `n` 大，所以還不到 subexponential 的極致），但已經足以推翻 ETH。

### 但必須加上 Fortnow 補的這一刀

> 「ETH 和 SETH 失效，**不代表它們的推論也失效**。而且這個演算法只適用 `k`-SAT，**對 NP 問題整體沒用**——Subset Sum 還是 `2^(n/2)`、TSP 還是 `2^n`。要讓整個 NP 都 subexponential，得把 3-SAT 做到 `2^(n^o(1))`，OpenAI 的結果離這個還很遠。」

所以正確的說法是：

> **✅「AI 推翻了『NP 難題必然指數級難』這個假設」**
> **❌ 不是「AI 證明了 P=NP」**
> **❌ 更不是「所有難題都能快速破解」**

**這個修正不會削弱論點，反而讓它更精準**——因為 ETH 被推翻，剛好就是在說「困難問題沒有我們想像的那麼困難」，這正是 WMW1 想主張的事。

### 順帶修掉「密碼會被破解」這個推理跳躍

原文從「RL 有方向性 → 破解更快 → 固定時間改密碼可能不夠」這條線，結論太強。ETH 被證偽的意思是「3-SAT 有比指數更快的演算法」，它**不代表**：

- ❌ AES-256 可以被快速破解——對稱加密的難度假設跟 ETH 無關
- ❌ RSA 可以被快速破解——那是**整數分解**，屬於 NP ∩ co-NP，OpenAI 的演算法**沒有**改善它
- ❌ 所有 NP 問題都變簡單了——Fortnow 明說 Subset Sum、TSP 都沒動

### 那業內到底在驚訝什麼？

Ryan Williams 的說法最傳神：

> 「有些部分你可能說它是常規的，但**有兩三個看起來像外星人寫的部分**——正是這些部分讓我覺得，哇，這是整個社群必須一起處理的東西。」

以及：

> 「ETH 的持久性讓它被寫進過去十年的很多論文。如果 AI 實驗室的說法成立，**這些論文都要重新檢視**。」

**真正的驚訝點有四層：**

1. AI 攻進的不是寫程式或做實驗，是**數學證明**——人類最後的智力高地之一。
2. 而且**有 Lean 形式化驗證**，代表這不是幻覺，機器可以逐行檢查。
3. **連 ETH 的提出者本人都下場驗證**，這不是「AI 胡說八道」的等級。
4. 它暗示：**RL + 大量採樣，已經能在「人類幾十年沒有突破」的空間裡找到路徑。**

第 4 點才是 WMW1 的開戰理由。因為**數學證明是「可驗證任務」的極致形態**——有 Lean 這種完美的驗證器，RL 可以無限自我進化而不會 reward hack。這裡就是驗證器最好的練兵場。

## 九、WMW1 的戰線圖

```
2026 之前：預訓練軍備競賽（誰的資料多、參數大）
                ↓ 資料見底、scaling 邊際遞減
2026~2028：WMW1
    ├─ 上半場：世界模型（模擬器品質 = 訓練資料品質）
    ├─ 中場：驗證器（reward model / 形式化驗證器）
    └─ 下半場：on-policy RL at scale（把上面兩者接起來狂跑）
```

為什麼我判斷這是主戰場？因為 on-policy RL 的瓶頸永遠是那兩個問題：

1. **資料從哪來？** → 沒有世界模型，只能在真實世界慢慢試（貴、慢、危險）
2. **怎麼知道對？** → 沒有好驗證器，只能 reward hacking（學到垃圾）

而「可驗證任務」現在已經被圈出四大塊：**數學、程式碼、遊戲、形式化證明**。它們的共同點是**機器能自己判斷對錯**，所以能跑無限輪自我進化。反過來說，「寫一份好的行銷文案」到現在還很難 RL，原因就是沒有自動驗證器。

> **這也回頭解釋了第一到六節**：自動駕駛之所以能從稠密融合走到端到端，
> 不是因為模型突然變聰明，而是因為**它終於有了「世界模型當訓練場 + 可驗證的獎勵當裁判」**。
> LiDAR 融不融合，在這個尺度上只是參數選擇而已。

## 十、名詞速查

### 感測器與架構

| 名詞 | 白話 |
|---|---|
| **LiDAR（光達）** | 打雷射測距的感測器，直接產出帶精確深度的 3D 點雲；缺點是貴、怕雨霧、沒有語意。 |
| **Point cloud（點雲）** | 光達回傳的一堆 3D 座標點，每個點是一次雷射反射。 |
| **Sensor fusion（感測器融合）** | 把不同感測器的資訊整合成同一個表徵。 |
| **稠密融合（dense fusion）** | 把資料鋪成密集網格再拼接，資訊完整但計算重。 |
| **稀疏特徵（sparse features）** | 只保留有意義的位置/查詢點，計算量跟物件數成正比。 |
| **Voxel（體素）** | 3D 版的像素。 |
| **BEV（Bird's Eye View）** | 俯視視角的統一表徵，常用來對齊多感測器。 |
| **Modality（模態）** | 一種資料類型，例如影像、點雲。 |
| **Sensor dropout** | 訓練時隨機關掉某個感測器輸入，逼模型學會缺資料也能跑。 |
| **Redundant module / training** | 為硬體不對稱設計的備援模組／備援訓練流程。 |
| **End-to-end（端到端）** | 一個網路從感測器直接算到駕駛輸出，中斷人工切分的模組介面。 |
| **Token** | Transformer 的輸入單位，一段向量。 |
| **Attention** | 讓模型自己決定「該關注哪個 token」的機制。 |
| **Encoder / Decoder** | 把輸入壓成特徵／把特徵轉成輸出。 |
| **Occupancy（佔用網格）** | 用 3D 格子表示「這裡有沒有東西」，端到端常見輸出。 |
| **ISO 26262 / SOTIF** | 車用功能安全／預期功能安全標準。 |
| **接管（disengagement）** | 自動駕駛失效、人類必須接手的事件，是衡量可靠度的核心指標。 |

### RL 與世界模型

| 名詞 | 白話 |
|---|---|
| **on-policy RL** | 只用「當前這版策略」產生的資料訓練；資料用完就丟，換新版重新採集。穩但貴。 |
| **off-policy RL** | 可以用舊版本的資料（存在 replay buffer），省但容易偏。 |
| **rollout** | 讓模型在環境裡「跑一遍」，產生一條軌跡。 |
| **policy（策略）** | 模型的行為函數：看到狀態 → 輸出動作的機率分佈。 |
| **reward（獎勵）** | 打分數的函數，RL 唯一的學習訊號。 |
| **reward hacking** | 模型鑽獎勵定義的漏洞，達標但沒做對事。 |
| **RLVR** | RL with Verifiable Rewards，用「機器可自動驗證」的獎勵做 RL（數學、程式碼）。 |
| **advantage（優勢）** | 某個動作比「平均而言」好多少，是 policy gradient 的權重來源。 |
| **exploration-exploitation** | 該繼續用已知好招，還是冒險試新招。 |
| **world model（世界模型）** | 能預測「我做了 A 之後世界會變怎樣」的模型，可當訓練場用。 |
| **pass@k** | 同題採樣 k 次、至少一次答對的機率。衡量探索能力的指標。 |

### 計算複雜度

| 名詞 | 白話 |
|---|---|
| **P / NP** | P：好解。NP：好驗證。P=NP 問「好驗證的是不是也好解」。**仍懸而未決**。 |
| **NP-complete** | NP 裡最難的一批，彼此可互相轉換。3-SAT 是代表。 |
| **3-SAT** | 「一堆三個變數的 OR 用 AND 串起來，有沒有解」——最經典的 NP-complete 問題。 |
| **ETH（指數時間假設）** | 假設 3-SAT 必須 `2^(cn)` 時間才能解。**2026/10 被 OpenAI 演算法推翻。** |
| **SETH** | ETH 的強化版，也一併失效。 |
| **subexponential** | 比指數慢，但仍比多項式快。ETH 被推翻的意義就在這裡。 |
| **Lean** | 形式化數學證明語言，證明可被機器逐行檢查——所以不是幻覺。 |

## 十一、一句話總結

> **第一層（架構）：「LiDAR 跟 camera 不相容」是稠密融合時代的遺產。**
> 那時候要靠人工設計的備援模組去縫合兩種型態、還要靠 sensor dropout 訓練去補硬體不對稱。
> 稀疏 token 化之後，兩者只是同一串序列裡的兩種詞，融合變成可學習的問題，工程稅大幅下降；
> 而硬體價格已經掉到「裝幾顆是產品決策而非技術決策」的量級。
>
> **第二層（範式）：真正讓這件事發生的，是訓練資料的生產方式換了。**
> on-policy RL 像多重影分身——幾千個平行時空的自己同時失敗，經驗彙總回本體。
> 魔法不在「AI 比較聰明」，而在**世界模型把時間從成本函數裡刪掉了**。
>
> **第三層（校正）：RL 只需要對錯、不需要正解，但「定義對錯」的門檻比「做出對錯」高得多**
> ——這就是 reward hacking 存在的原因。知識貶值，**判斷標準升值**。
> 而 RL 是「有方向的窮舉」，比窮舉省，但**沒省到可以忽略**；它可能自信地卡在一個還不錯的錯答案上。
>
> **第四層（戰局）：WMW1 的真正戰場不是模型，是「世界模型 + 驗證器」這一對。**
> 2026 年 10 月 ETH 被推翻，是這場戰爭的第一聲炮響——因為數學證明有 Lean 這種完美驗證器，
> 是 RL 最理想的練兵場。**但被推翻的是 ETH，不是 P≠NP**；P vs NP 仍懸而未決，
> 現有加密系統也沒有被動搖。業內驚訝的不是「密碼要完蛋了」，而是
> **AI 已經能在人類幾十年沒突破的空間裡找到路徑。**
>
> **而這整件事，也回頭解釋了第一層**：自動駕駛之所以能走到端到端，
> 是因為它終於有了「世界模型當訓練場 + 可驗證的獎勵當裁判」。
> 在那個尺度上，**LiDAR 融不融合，真的只是參數選擇而已。**
