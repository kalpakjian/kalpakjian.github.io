## 一段話總結（TL;DR）

Teachable Machine（下稱 TM）是 Google 免費的網頁工具（自 2017 年推出的「AI 實驗」），讓任何人在
瀏覽器內用範例訓練機器學習模型——可以是**圖像、聲音或身體姿勢**——**無需編程、無需專業知識**。
流程只有三步：**收集**（把範例分組）→ **訓練** → **匯出**。訓練在**本機**進行，圖像不會被上傳；
TM 產出的是**真正的 TensorFlow.js 模型**，可在任何執行 JavaScript 的環境運行（Glitch、p5.js、
Node.js）。簡報後半部是一個警示故事：用香蕉訓練出來的模型，只學到「與標籤相關的像素規律」，所以
遇到兩隻香蕉、換了背景或光線、甚至只是香蕉的照片／圖畫／玩具，都會出錯。要提升穩健度，靠的是更
大及更多樣化的樣本、乾淨背景與一致光線，以及不同的擺放方向。簡報最後帶出實作項目：**「以
Teachable Machine 與 p5.js 製作機械蛇」**。

## 2. Teachable Machine 是甚麼？[p. 2–3]

| 問題 | 簡報的答案 |
|---|---|
| 是甚麼？ | 一個**網頁工具**，令建立機器學習模型變得*快速、容易、人人可用*。 |
| 可以做甚麼？ | 「訓練電腦辨認你自己的**圖像**、**聲音**及**姿勢**。」 |
| 對象是誰？ | 網站、應用程式等——**無需專業知識或編程**。 |
| 由誰開發？ | 一個**來自 Google 的 AI 實驗**，**自 2017 年**運作至今。 |
| 網址 | `https://teachablemachine.withgoogle.com/` |

**重點：** TM 移除了機器學習的常見門檻——不用建立資料管線、不用設置 GPU、不用寫 Python、也不用
懂模型架構。你只需在瀏覽器提供範例，就能得到一個模型。

## 3. 三步工作流程 [p. 4]

該頁展示 TM 的標準循環，並以「類別一／類別二」的小狗圖片示意：

| 步驟 | 名稱 | 你在做甚麼（簡報原文意思） |
|---|---|---|
| 1 | **收集（Gather）** | 「把範例收集並分組為類別，即你想電腦學會分辨的項目。」 |
| 2 | **訓練（Train）** | 按下 **TRAIN MODEL**，「然後即時測試，看它能否正確分類新範例。」 |
| 3 | **匯出（Export）** | 「把模型匯出到你的專案：網站、應用程式等。你可以**下載模型，或免費把它寄存於網上**。」 |

**核心概念：** 一個*類別*（class，亦稱標籤／label）就是一組代表同一意義的範例（例如「熟」、「未熟」）。
模型最終學到甚麼，取決於這些「桶」的質素與平衡。

## 4. 可以教它甚麼？—— 三種專案類型 [p. 5]

| 類型 | 分類對象 | 如何提供樣本 | 簡報例子 |
|---|---|---|---|
| **圖像（Images）** | 圖片／攝影機畫面 | 上載**檔案或使用網絡攝影機** | 「Me + Dog <3」對「Just Me」 |
| **聲音（Sounds）** | 短音訊片段 | **錄製**短聲音樣本（WAV/MP3 等檔案支援「即將推出」） | 「Snap」對「Clap」 |
| **姿勢（Poses）** | 身體位置 | **檔案，或在攝影機前擺出姿勢** | 「Stand」對「Squat」 |

每個示例的媒體下方都顯示了附標籤的信心度橫條——即 TM 永遠輸出**每個類別的機率**，而非單一答案。
這一點在後文「模型混淆」時非常重要。

## 5. TM 模型運行在哪裡？TensorFlow.js 與 TensorFlow [p. 6–7]

**TensorFlow.js [p. 6]**
- 「用 Teachable Machine 製作的模型是**真正的 TensorFlow.js 模型**，可在**任何執行 JavaScript 的
  地方**使用。」
- 因此它們能與 **Glitch、p5.js、Node.js 等**工具「好好配合」。
- 實際意義：TM 模型就是一個網頁資源，用 `<script>` 標籤載入即可在瀏覽器 sketch 中使用——不需要
  伺服器，也不需要 Python。

**TensorFlow [p. 7]**
- 「一個**開源程式庫**，用於數值運算及**大規模機器學習**。」
- 「由 **Google Brain 團隊**開發，原本供 Google 內部使用。」
- 「可**訓練及運行深度神經網絡**。」

**整個技術堆疊的心智模型：**

```
TensorFlow            ← 底層開源機器學習程式庫（Google Brain）
   └── TensorFlow.js      ← JavaScript 版本；在瀏覽器／Node.js 執行模型
          └── Teachable Machine   ← 負責訓練及匯出 TF.js 模型的友善網頁介面
                 └── 你的專案（p5.js sketch、Glitch 應用、網站……）
```

## 6. 實例：香蕉有多熟？[p. 8]

簡報的主線例子是一個**四類圖像分類器**：

| 類別 | 意思 |
|---|---|
| `Too early`（太早） | 綠色／未熟 |
| `Ripe`（熟） | 黃色、可食用 |
| `Too late`（太遲） | 過熟／轉褐 |
| `No banana`（沒有香蕉） | 畫面中沒有目標物 |

**該頁指示：**「建立四個類別……為每個類別提供圖像樣本讓它學習。」

**溫習提示：** `No banana` 這個類別是值得記住的設計模式——永遠要有一個「以上皆非」的類別，否則
模型在每一格畫面都必須從你的物件類別中挑一個。

## 7. 訓練 [p. 9]

該頁兩條規則：

1. **「模型在你自己的電腦（PC）本機訓練——沒有任何訓練資料（圖像）被上傳。」**
   → 私隱好處：你的攝影機照片不會離開電腦，也沒有伺服器端訓練成本。
2. **「訓練期間不要切換分頁！」**
   → 訓練就在該瀏覽器分頁內進行；切換到其他分頁可能令訓練停滯或中斷。完成前請保持該分頁在前景
   並處於使用中狀態。

## 8. 預覽 [p. 10]

預覽面板就是**評估**模型的地方：

- **輸入：** `Webcam`（附開／關切換）——亦可改用上載的圖片預覽。
- **輸出：** 每個類別一條橫條，顯示**百分比**。
- 該頁展示同一模型的三格畫面，每個都正確地給出 **100 %**：

| 畫面 | 物件 | 模型輸出 |
|---|---|---|
| 1 | 手中綠色香蕉 | `Too Early` 100 % |
| 2 | 手中黃色香蕉 | `Ripe` 100 % |
| 3 | 帶斑點／轉褐的香蕉 | `Too Late` 100 % |

**教訓：** 同分佈的輸入（同類物件、同一隻手、同一中性背景）可以看起來完美。但這*並不*證明模型能
推廣到其他情況——見第 11–14 節。

## 9. 匯出模型 [p. 11]

「你可以把模型匯出，在專案中使用。」

匯出對話框提供三個目標：

| 目標 | 適用情況 |
|---|---|
| **TensorFlow.js** | 網頁、p5.js、Glitch、Node.js（本課程採用這個） |
| **TensorFlow** | 桌面／伺服器／Python 工作流程 |
| **TensorFlow Lite** | 流動裝置及嵌入式裝置 |

另有兩種交付方式：

- **上載（可分享連結）** → TM 會**免費**把模型寄存於類似
  `https://teachablemachine.withgoogle.com/models/[...]` 的網址
- **下載** → 取得模型檔案，自行寄存

對話框亦會產生**程式碼片段**，分為 **JavaScript** 與 **p5.js** 兩個分頁。簡報所示的 JavaScript
片段包括：

```html
<div>Teachable Machine Image Model</div>
<button type="button" onclick="init()">Start</button>
<div id="webcam-container"></div>
<div id="label-container"></div>
<script src="https://cdn.jsdelivr.net/npm/@tensorflow/tfjs@1.3.1/dist/tf.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/@teachablemachine/image@0.8/dist/teachablemachine-image.min.js"></script>
<script type="text/javascript">
  // More API functions here:
  // https://github.com/googlecreativelab/teachablemachine-community/tree/master/libraries/image

  // the link to your model provided by Teachable Machine export panel
</script>
```

**重點歸納：**
- 三個要素：一個**容器 div**、一個**啟動按鈕**，以及**兩個程式庫**
  （`@tensorflow/tfjs` 與 `@teachablemachine/image`）。
- 匯出面板給你的模型網址，就是把網頁連接到你訓練成果的關鍵。
- 若要把模型嵌入 p5.js sketch（例如機械蛇示範），請選 **p5.js** 分頁而非 JavaScript。

## 10. 機器學習有其限制 [p. 12]

全份簡報最重要的一頁概念：

> 「圖像對電腦而言，只是**一堆數字與像素規律**。所以你並沒有真正教會它『香蕉是甚麼』……我們教
> 會它的，是『**這個**——背景上的一團黃色形狀——被標籤為熟香蕉』——對電腦來說，這一切都只是
> 像素。」

**意思是：**

| 人類的理解 | 模型實際學到的 |
|---|---|
| 「香蕉是彎曲、有果皮的水果」 | 與*你的*拍攝條件綁定的像素顏色／邊緣統計規律 |
| 能推廣到任何地方的香蕉 | 只推廣到在統計上與訓練照片相似的輸入 |
| 明白「熟」的意義 | 只知道你把哪個標籤貼在哪種像素規律上 |

→ 所以簡報後半部全都在講**如何在訓練條件以外進行評估**。

## 11. 失敗案例一 —— 兩隻香蕉 [p. 13]

**「遇到兩隻香蕉就混亂？」**
簡報給出的原因：*「模型在訓練時從未見過這樣的樣本。」*

**診斷：** 訓練集中不存在的物件數量／形狀組合，實際上就是**未見過的輸入**。TM 的分類器不會偵測
「香蕉物件」，它比對的是整體視覺規律；兩隻香蕉同時帶有黃色與綠色形狀，可能同時像 `Ripe` 與
`Too early`，於是信心度被攤分。

**改善方向：** 若模型日後會在這種情況下使用，就要在訓練資料加入多物件、部分遮擋的樣本。

---

## 12. 失敗案例二 —— 不同背景與光線 [p. 14–15]

簡報問：*「在同一批香蕉上，換一個不同顏色的牆壁等背景測試——它還行嗎？」* 答案是：*「在這個新
背景下，它有幾個類別開始有點混亂。」*

示範截圖 [p. 15] 把同一隻黃色（熟）香蕉放在**深紅色背景**：

| 畫面中的物件 | 模型輸出（約數） |
|---|---|
| 綠色香蕉 | `Too Early` ≈ 70 %、`Ripe` ≈ 30 % |
| 黃色香蕉 | `Ripe` ≈ 60 %、`Too Early` ≈ 30 %（其餘攤分） |

**與 [p. 10] 比較：** 同一隻香蕉在接近訓練條件的背景下是 **100 %**。信心度下降完全是因為
**背景／光線改變**，而不是香蕉本身改變。

**診斷：** 背景也是輸入的一部分。深紅色牆壁從未出現在樣本中，模型學到的規律因此不再吻合。

## 13. 補救 —— 讓模型更穩健 [p. 16]

> 「加入更多**不同環境**下的香蕉照片，讓模型更穩健，以便在不同背景下也能運作。」

**原則：** 穩健度是用**資料多樣性**換回來的，而不是靠「更好的演算法」。你預期在推論時會遇到的
每種環境，都應在訓練中出現。

---

## 14. 失敗案例三 ——「試著騙它！」[p. 17]

> 「舉起一張香蕉照片！或者一幅香蕉圖畫！又或者一個看起來像香蕉的玩具！」

截圖：一幅**小朋友畫的香蕉**被判為 `Ripe` ≈ **88 %**（`Too Early` ≈ 8 %）。

**為何值得注意：** 模型從未見過這種「非真實物件」，卻非常有信心地說「熟」——這清楚證明驅動預測的
是顏色／形狀規律，而非物件身份。它同時說明模型可以被欺騙：一張香蕉*照片*並不是香蕉，但對模型
而言像素相同。

**考試式重點：** 高信心度 ≠ 正確；分類器的輸出是**相似度判斷**，不是真理宣稱。

## 15. 影響穩健度的因素與改善方法 [p. 18]

該頁清單（依原結構，並補上「為甚麼」）：

| 因素 | 簡報建議 | 為何有效 |
|---|---|---|
| **樣本數量與多樣性** | 「每個類別的樣本數量要更多，**種類要更多**」 | 覆蓋更多輸入空間 → 減少未見過的情況 |
| **背景與光線** | 「**乾淨的背景**、**一致的光線**會更好」 | 模型能聚焦物件，而非背景雜物／陰影規律 |
| **擺放方向** | 「樣本要包含物件**不同方向**的圖像」 | 旋轉／翻轉是巨大的像素變化，沒有範例時模型會視為新事物 |

**實用取樣清單（由上述推導）：**
1. 每類至少 50–100 張有變化的照片（越多越好；各類別數量盡量平衡）。
2. 變化距離、角度、方向、手持位置。
3. 若實際部署環境背景多變，才需要在訓練中變化背景；否則寧可保持一致。
4. 保持光線一致，避免強烈陰影。
5. 加入 `No banana`／背景類別。
6. 在預覽中改用**真實部署環境**的輸入重測，而不是訓練環境的輸入。

## 17. 一頁摘要（溫習用）

**定義** —— Teachable Machine：Google 免費的瀏覽器工具（2017 年起的 AI 實驗），可無需編程訓練
圖像／聲音／姿勢分類器。

**流程** —— **收集**（把範例分組）→ **訓練**（本機進行、分頁保持在前景）→ **匯出**（TF.js／TF／
TF Lite；可分享連結或下載；附 JS 與 p5.js 片段）。

**產出** —— 真正的 **TensorFlow.js** 模型 → 可在任何 JS 環境運行（Glitch、p5.js、Node.js）。

**例子** —— 香蕉成熟度：`Too early`／`Ripe`／`Too late`／`No banana`。

**核心限制** —— 「圖像只是數字與像素規律。」模型學到的是「*這個背景上的黃色形狀＝熟*」，而不是
「香蕉」。高信心度是相似度判斷，不是真理。

**三個示範失敗** ——（1）兩隻香蕉（未見過）→ 混亂；（2）新背景／光線 → 信心度由 100 % 跌至
≈ 60 %；（3）圖畫／玩具香蕉 → 仍判為 `Ripe` ≈ 88 %。

**穩健度槓桿** —— 樣本數量與多樣性；乾淨背景與一致光線；多種方向；加入你將部署的環境。

**最終項目** —— 「以 Teachable Machine 與 p5.js 製作機械蛇」。

## 18. 關鍵詞

| 詞彙 | 在本課程的意思 |
|---|---|
| **類別／分類／標籤（class / label）** | 模型要辨認的一組同名範例（例如 `Ripe`） |
| **樣本（sample）** | 為某類別收集的一張照片、一段聲音或一個姿勢 |
| **訓練（training）** | TM 從你的樣本中學習的過程（此處在瀏覽器本機進行） |
| **模型（model）** | 已訓練的成品，把輸入映射為各類別的機率 |
| **預覽／推論（preview / inference）** | 用模型處理新輸入，並讀取信心度橫條 |
| **信心度／機率（confidence）** | TM 為每類別顯示的百分比；各類合計約 100 % |
| **穩健度（robustness）** | 條件改變（背景、光線、角度、物件）時模型仍能正常運作的程度 |
| **TensorFlow.js** | 在瀏覽器／Node.js 執行 TF 模型的 JS 程式庫 |
| **Teachable Machine** | 負責訓練及匯出上述模型的無代碼網頁介面 |
| **p5.js** | 創意編程 JS 程式庫，用來驅動視覺示範（機械蛇） |

## 20. 自我檢測問題

1. **TM 工作流程的三個步驟是甚麼？**
   收集 → 訓練 → 匯出。[p. 4]
2. **TM 可以學哪三類東西？**
   圖像、聲音、姿勢。[p. 5]
3. **訓練在哪裡進行？有甚麼資料會離開你的電腦？**
   在本機（PC）進行；沒有任何訓練圖像被上傳。[p. 9]
4. **為何訓練期間不可切換分頁？**
   訓練在該瀏覽器分頁內執行；離開可能令訓練中斷或停滯。[p. 9]
5. **供網頁使用時，TM 匯出的是哪種模型？**
   真正的 TensorFlow.js 模型，可在任何執行 JavaScript 的地方運行。[p. 6]
6. **匯出提供哪三個目標格式？**
   TensorFlow.js、TensorFlow、TensorFlow Lite。[p. 11]
7. **為何需要 `No banana` 類別？**
   讓模型在畫面沒有目標物時仍有合法標籤；否則它被迫從物件類別中選一個。[p. 8]
8. **為何模型遇到兩隻香蕉會出錯？**
   訓練時從未見過這類樣本 → 實際上等於未見過的輸入。[p. 13]
9. **在紅色背景下準確度為何下降？**
   背景與光線是輸入的一部分；新背景未在訓練中出現。[p. 14–15]
10. **影響穩健度的三個因素是甚麼？**
    樣本數量與多樣性；背景與光線；擺放方向。[p. 18]
11. **模型不穩健時的補救方法是甚麼？**
    加入更多不同環境下的圖像（並增加多樣性與方向）以提升穩健度。[p. 16]
12. **一幅香蕉圖畫被判為 `Ripe` ≈ 88 %，證明了甚麼？**
    模型比對的是像素規律，而非「香蕉」這個概念——高信心度 ≠ 正確。[p. 12、17]
