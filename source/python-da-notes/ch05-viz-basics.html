C.R.U.D.

在計算機程式設計中，創建、讀取、更新和刪除（CRUD）是持久存儲的四個基本操作。CRUD 有時還用於描述使用者介面約定，這些約定有助於使用基於計算機的表單和報告查看、搜索和更改資訊。

RESTful API

RESTful API 是應用程式介面（API）的一種架構樣式，它使用 HTTP 請求來訪問和使用數據。

CRUD 和 RESTful 是類似的方法。RESTful 服務使用特定的 HTTP 方法，如 GET、POST、PUT 和 DELETE，並要求數據採用 JSON 或 XML 等格式。CRUD 更簡單，非常適合小型專案；REST 為更大、更複雜的系統提供了更大的靈活性和可擴充性。

NoSQL

  • 不僅 SQL（Not Only SQL）

  • 有時數據無法以這種結構化的方式進行組織。您可能需要一種更有效的方式來存儲和訪問大量數據。

• 資料庫通常被稱為非關係資料庫，它們有各種形狀和大小。

  • 眾所周知的 NoSQL

一. MongoDB - 將資料物件存儲在集合和文檔中，而不是表和行中

二. Redis - 儲存 hash、點陣圖、地理空間索引、位字段等數據類型

三. RavenDB - 面向文件的資料庫，將資料儲存為 JSON 文件

在我們的研究範圍內，我們涵蓋了 SQL 基礎知識以及五個流行的資料庫管理系統的細微差別：Microsoft SQL Server，MySQL，Oracle 資料庫，PostgreSQL 和 SQLite。

SQL 語句

  • 這是可以編寫以執行任何 CRUD 操作的通用 SQL 代碼。擁有執行此類任務（編寫語句）的權利的人是資料庫管理員。

SQL 查詢

  • 需要訪問資料（從表中讀取）的使用者，執行查詢以查找和顯示。數據分析師和數據科學家就是這些使用者之一。他們可能擁有資料庫的唯讀許可權。

SQL 語句包括更廣泛的操作集，例如 INSERT、UPDATE、DELETE、CREATE、ALTER 和 DROP。

查詢是專門檢索數據並說明闡明其在 SQL 語言中的獨特角色的語句。

查詢

最基本的 SQL 查詢是：

SELECT * FROM my_table;

  • 意思是向我顯示名為 my_table 的表中的所有數據（包括所有列和行）。

• 大寫和小寫格式不是強制執行的，但為了可讀性，這是一個很好的樣式約定。

  • 查詢中的大寫單詞稱為關鍵字，這意味著 SQL 已保留它們以對數據執行某種操作。

所有其他單詞均為小寫。這包括表名、列名等。

• 為了在表上查找特定數據，我們可以查詢如下內容：

SELECT *

FROM my_table

WHERE column1 > 100

ORDER BY column2 ;

p.129

SQL 查詢包含以下子句的組合：

SELECT -- columns to display FROM -- table(s) to pull from WHERE -- filter rows GROUP BY -- split rows into groups HAVING -- filter grouped rows ORDER BY -- columns to sort

執行順序

SQL 代碼按一定的順序執行。如果訪問的數據量很大，查詢方式會影響返回結果的速度。

執行查詢后，這是電腦處理資料的順序：

  • SELECT - 指定要使用 SELECT 顯示的欄位

  • FROM - 使用 FROM 收集所有資料

  • WHERE - 使用 WHERE 篩選資料列

  • GROUP BY - 將行與 GROUP BY 一起分組

  • HAVING - 使用 HAVING 篩選群組行

  • ORDER BY - 使用 ORDER BY 重新排列結果

HAVING 子句 對從 GROUP BY 查詢返回的行施加限制。換言之，它允許您在應用 GROUP BY 後對結果進行篩選。

SELECT t.name AS tour_name,
COUNT(*) AS num_waterfalls
FROM waterfall w INNER JOIN tour t
ON w.id = t.stop
GROUP BY t.name
HAVING COUNT(*) = 6;
tour_name num_waterfalls
M-28 6
Munising 6

WHERE Versus HAVING

The purpose of both clauses is to filter data. If you are trying to:

  • Filter on particular columns, write your conditions within the WHERE clause

  • Filter on aggregations, write your conditions within the HAVING clause

The contents of a WHERE and HAVING clause cannot be swapped:

  • Never put a condition with an aggregation in the WHERE clause. You will get an error.

  • Never put a condition in the HAVING clause that does not involve an aggregation. Those conditions are evaluated much more efficiently in the WHERE clause.

請注意，movies 表有一個 id 列，用於唯一標識每部電影，以及電影標題和電影發行年份的列。people 表還具有 id 列，並且還具有每個人的姓名和出生年份的列。

同時，電影評級存儲在評級表中。表中的第一列是 movie_id：引用 movies 表的 id 的外鍵。該行的其餘部分包含有關每部電影的評分以及該電影在 IMDb 上獲得的票數的數據。

最後，明星和導演表將人們與他們表演或導演的電影相匹配。（僅包括主要明星和導演。每個表只有兩列：movie_id 和 person_id，分別引用特定的電影和人物。

擺在您面前的挑戰是編寫 SQL 查詢，通過從一個或多個表中選擇數據來回答各種不同的問題。

SELECT title, rating FROM movies

JOIN ratings ON movies.id=ratings.movie_id

WHERE ratings.rating NOT NULL

AND movies.year = 2010

ORDER BY rating DESC, title ASC;

People with the same birth year may be listed in any order.

If a person appeared in more than one movie in 2004, they should only appear in your results once.

SELECT name FROM people WHERE id IN

(SELECT person_id FROM stars JOIN movies

ON movies.id = stars.movie_id

WHERE movies.year = 2004) ORDER BY birth;
