# 第 1 章 · 計算思維與網頁框架基礎

**本章導讀**

- **上半章｜計算思維**：認識解決問題的五個核心能力——分解、模式識別、抽象、算法，以及如何判斷問題的困難度與可解性。
- **下半章｜網頁框架開發**：搞懂網站是怎麼運作的，以及前端、後端、瀏覽器各自負責什麼，最後看 UML 如何用來分析與設計網站系統。

## 1. 計算思維特徵

計算思維（Computational Thinking）就是「用電腦的方式思考」：把複雜問題拆開、找出規律、化繁為簡，再設計出可執行的步驟。它由五個互相搭配的特徵組成，以下逐一說明。

### 1.1 分解（Decomposition）

**一句話**：把大問題拆成小問題。

**做法**

- **由上而下**：先切成主要子問題，再逐層往下細分，直到小到可以直接解決。
- **依角度切**：可以按「關鍵因素」、「子任務功能」或「不同層次」來拆。
- **保持獨立**：子問題之間盡量互不依賴，才能各自處理、互不干擾。
- **大小適中**：太大會難以處理，太小又失去意義。

**好處**：拆小之後，每個子問題都能選用最合適的方法（如資料分析、建模、演算法）；最後把各子問題的解法拼起來，就是整體解答。

**重點**：分解的關鍵是「層次化、獨立性、適量性」。

### 1.2 模式識別（Pattern Recognition）

**一句話**：在問題或資料中看出重複出現的模式、趨勢與規律。

**用途**：從大量資料中抓出關鍵特徵，用來推測、預測或解釋現象。常見於機器學習、人工智慧、資料分析、影像處理等領域。以下從五個角度說明主要方法。

#### 1.2.1 特徵提取

先從資料中找出「有代表性、能描述現象」的特徵。特徵可以是數字、文字或圖像，通常靠統計、訊號處理或機器學習來提取。

#### 1.2.2 分類與識別

- **分類**：把資料分到不同類別。
- **識別**：判斷一筆資料屬於哪個類別。

常用統計模型、機器學習或神經網路來完成。

#### 1.2.3 聚類分析

在沒有事先分類的情況下，把相似的資料自動歸成一組。同一群內相似度高、不同群之間相似度低，可用來發現資料的關聯與潛在結構。

#### 1.2.4 模型建立與預測

建立模型（數學、統計或機器學習模型）來描述資料中的規律，再用它預測未來、模擬或最佳化，並據此做出決策。

#### 1.2.5 特徵選擇與維度降低

資料維度太高會造成「維度災難」與運算困難。

- **特徵選擇**：只留下最具代表性的特徵。
- **維度降低**：把高維資料轉成低維表示。

兩者都能提升分析效率、降低計算成本。

**重點**：模式識別的成效取決於資料品質、特徵選擇與模型設計，也需要不斷回饋與調整。
### 1.3 抽象（Abstraction）

**一句話**：只留重要的，忽略不重要的細節。

把問題的核心概念抽出來、把不相關的細節拿掉，讓問題更容易理解和處理。它能將複雜現象簡化成模型或表示形式，幫助我們從更高的層次思考。

#### 1.3.1 目的

聚焦在問題的本質與關鍵關係，剝離次要細節，以便做更系統、更高階的分析。

#### 1.3.2 層次

抽象可以分層進行：

- **高層次**：看整體系統的結構與功能。
- **低層次**：往下細分成更小的模組或單元，考慮其特性與互動。

層次化能建立清晰的結構，把複雜問題拆成好處理的部分。

#### 1.3.3 方法

常見做法是挑出關鍵特徵與重要概念，抽象成更通用的符號或表示形式，例如數學公式、圖形、統計模型、邏輯符號；也可以把問題建模成簡化系統，抓住它的基本行為。

#### 1.3.4 優點

- 能快速掌握問題的核心。
- 同一套思維與解法可套用到不同情境（通用性高）。
- 有助於設計更易理解、維護與擴充的模組化結構。

#### 1.3.5 挑戰

- 要判斷「哪些細節可以省略」。
- 要拿捏簡化與遺漏的平衡：過度簡化會漏掉重點，過度詳細又會變得難懂。

因此，選對抽象層次與方法本身就是一項挑戰。

**重點**：抽象能幫我們看清問題本質、提供更通用的模型，但要小心簡化與遺漏之間的取捨。

### 1.4 算法（Algorithm）

**一句話**：把「怎麼做」寫成一組明確、可依序執行的步驟。

算法是計算思維的核心，讓人能有系統地分析問題、設計解法並完成任務。以下說明它的幾個重要面向。

#### 1.4.1 步驟與指令

算法由一個或多個步驟組成，每個步驟是一條明確指令，描述如何從一個狀態走到下一個狀態。指令可以是基本計算、邏輯判斷、條件或迴圈，也可以是更複雜的操作。

#### 1.4.2 問題解決能力

算法的目標就是解決問題。它提供一套系統性做法：定義問題 → 分析問題 → 設計解法 → 完成解決。好的算法能更有效率地處理各種問題。

#### 1.4.3 效率與最佳化

好的算法要在合理時間內完成任務。效率通常看兩件事：

- **時間複雜度**：執行所需時間。
- **空間複雜度**：執行所需記憶體。

最佳化就是透過分析與改良，提升效率。

#### 1.4.4 問題分解與抽象

設計算法時，通常先把問題分解成子問題、逐一設計解法；同時用抽象把關鍵概念與變數化成更一般的形式，讓算法適用範圍更廣。

#### 1.4.5 結構與設計

常見的算法結構有三種：

- **順序結構**：依序執行步驟。
- **循環結構**：重複執行步驟。
- **分支結構**：依條件選擇不同步驟。

選對資料結構與算法模型，是設計高效算法的關鍵。

**重點**：好的算法要「高效、可行、設計良好」，這是計算思維中最核心的技巧。

### 1.5 問題的困難度與可解性

算法有一個重要特性：它只能解決「可解」的問題。

- 有些問題在計算上**無法解決**（不可解問題）。
- 但對大多數問題而言，只要存在有效算法，就能找到解法。
- 問題的**困難度**會影響算法的選擇、可行性與效率。

**本章小結**：計算思維的五個特徵彼此交織、互相支持。用「計算的方式」思考，能幫助我們更有條理地處理各種問題。

**延伸閱讀**

- Craig Larman, *Applying UML and Patterns*
- Grady Booch, James Rumbaugh, Ivar Jacobson, *The Unified Modeling Language User Guide*
## 2. 網頁框架開發基礎

網站本質上就是一群存在伺服器上的檔案，透過網際網路讓使用者存取。以下先拆解「網站是怎麼運作的」，再分別看前端、後端、瀏覽器與 UML 扮演的角色。

### 2.1 網站運作的基本要素

#### 2.1.1 域名（Domain Name）

網站在網路上的唯一地址（例如 www.example.com）。使用者在瀏覽器輸入域名即可存取；域名需向註冊商註冊，並指向網站所在伺服器的 IP 位址。

#### 2.1.2 Web 託管（Web Hosting）

把網站檔案放在伺服器上、讓網路使用者可以存取的服務。託管商提供儲存空間與確保網站可用的技術；伺服器則是負責處理 HTTP 請求、回傳內容的電腦。

#### 2.1.3 前端開發（Front-End）

前端是使用者看得到、能互動的部分，涵蓋版面設計與介面（UI）。

- **HTML**：內容與結構。
- **CSS**：外觀與排版。
- **JavaScript**：互動與動態行為。
- **前端框架／函式庫**（如 React、AngularJS）：提供現成元件，加快開發。

#### 2.1.4 後端開發（Back-End）

後端負責伺服器端的運算：處理資料、產生前端要顯示的動態內容。常用語言有 PHP、Python、Ruby、Java 等；資料庫（如 MySQL、PostgreSQL、MongoDB）則負責儲存與管理資料。

#### 2.1.5 內容管理（CMS）

內容管理系統讓非工程師也能建立與管理網站內容。常見平台有 WordPress、Drupal、Joomla；它們提供範本與主題，不需大量寫程式就能調整外觀。

#### 2.1.6 客戶端與伺服器之間的通信

使用者造訪網站時，瀏覽器（客戶端）送出 HTTP 請求，伺服器回傳對應檔案（HTML、CSS、JavaScript、圖片等）。這種通信可以：

- **無狀態**：每個請求各自獨立。
- **有狀態**：用 cookie 或 token 記住會話資訊。

#### 2.1.7 網站安全

安全是防止威脅、保護使用者隱私的關鍵。常見措施：

- **加密**：用 HTTPS 等協定保護傳輸中的資料。
- **身分認證**：用登入、密碼與角色控管存取權限。
- **輸入驗證**：檢查使用者輸入，避免惡意資料或程式碼。
- **防護措施**：防範 XSS、SQL 注入、DDoS 等攻擊。

### 2.2 維護與更新

網站需要定期維護，才能保持正常、快速且安全：

- **故障修復**：處理影響運作或體驗的錯誤。
- **效能優化**：用快取、CDN、程式碼優化等提升速度。
- **相容性**：確保在各種裝置與瀏覽器都能正常運作。
- **內容管理**：定期更新內容，維持新鮮度與吸引力。

**重點**：網站的運作，靠的是域名、託管、前後端開發、內容管理、前後端通信、安全與定期維護這些環節共同配合。

### 2.3 前端開發

前端就是「使用者在瀏覽器裡看到、能互動的部分」，重點在打造順暢、好用的體驗。主要組成如下：

1. **HTML（超文本標記語言）**：網頁的骨架，用標籤定義標題、段落、清單、圖片、連結等元素。
2. **CSS（層疊樣式表）**：控制外觀與排版——顏色、字體、間距、版面；把樣式與結構分離，讓全站風格一致又好維護。
3. **JavaScript**：讓網頁能互動，例如表單驗證、輪播、下拉選單；也能用 AJAX 向伺服器非同步要資料。
4. **前端框架與函式庫**：提供現成元件與標準做法（如 React、Angular、Vue.js；jQuery、Bootstrap），加快開發。
5. **響應式網頁設計**：用 CSS 媒體查詢與彈性版面，讓網站在桌機、筆電、平板、手機都正確顯示。
6. **瀏覽器相容性**：確保在 Chrome、Firefox、Safari、Edge 等瀏覽器表現一致，必要時做修正與回退。
7. **可用性與使用者體驗（UX）**：追求直覺好用的介面，考量資訊架構、視覺層次、導覽與無障礙。
8. **效能優化**：透過壓縮程式碼、壓縮檔案、優化圖片、快取與延遲載入，縮短載入時間（也影響 SEO）。
9. **建置工具與任務管理器**：用 npm／Yarn、Webpack／Gulp、Grunt 等自動處理重複工作、管理相依、打包與優化。
10. **版本控制**：用 Git 追蹤變更、協作與管理程式碼，能同時作業、還原版本、合併修改。
11. **除錯與測試**：用瀏覽器開發者工具找問題；用 Jest、Selenium 等框架自動化測試，確保品質。
12. **前端安全**：做好輸入驗證、資料清理、防範 XSS，並遵循安全最佳實務。
### 2.4 伺服器後端網絡應用基礎

後端是網站的「伺服器端」，負責處理邏輯、儲存資料、與前端交換資料。主要組件如下：

1. **伺服器端程式語言**：處理業務邏輯，常見有 Python、Ruby、PHP、Java、C#、Node.js、Go 等。
2. **後端框架**：提供路由、請求處理、資料庫存取、認證等現成工具，例如 Django、Ruby on Rails、Express、Laravel。
3. **資料庫管理系統（DBMS）**：負責資料的儲存、檢索與管理，如 MySQL、PostgreSQL、Oracle、SQL Server、MongoDB；開發者以 SQL 等查詢語言操作。
4. **RESTful API**：定義前後端溝通的規範，讓資料交換可靠、可預測。
5. **身分驗證與授權**：確認使用者身分、決定其存取權限，常見機制有 RBAC、Token-based 驗證、OAuth。
6. **快取**：把常用資料暫存以加快回應，如 Redis、Memcached、Varnish。
7. **伺服器管理與部署**：選擇架構、設定環境、效能調校、負載平衡與容錯，並做好備份、監控與日誌。
8. **安全性**：防範 XSS、CSRF、SQL 注入等攻擊，並對資料做驗證與過濾。
9. **Web 服務與第三方整合**：串接金流、郵件、地圖等外部服務，並確保介面與規範一致。

**重點**：後端是網站能否「動起來」的關鍵，負責把資料、邏輯與安全都處理好。

### 2.5 瀏覽器

瀏覽器負責把網頁內容解析並顯示給使用者。它的主要組件與流程如下：

1. **使用者介面（UI）**：網址列、導覽按鈕、書籤列等，讓使用者操作瀏覽器。
2. **渲染引擎**：解析網頁內容並顯示，如 WebKit（Chrome、Safari）、Blink（Chrome、Opera）、Gecko（Firefox）。
3. **HTML 解析器**：把 HTML 解析成 DOM，描述網頁的結構。
4. **CSS 解析器**：把 CSS 解析成 CSSOM，決定元素的樣式。
5. **JavaScript 解釋器**：解析並執行 JavaScript，如 V8（Chrome、Opera）、SpiderMonkey（Firefox）。
6. **DOM 構建與渲染樹**：結合 DOM 與 CSSOM 建立渲染樹，決定要顯示哪些可見元素。
7. **佈局與繪製**：計算每個元素的位置與大小，再把它們畫到畫面上。
8. **顯示網頁**：把結果送到螢幕、行動裝置或印表機等輸出裝置。
9. **網路與資源載入**：送出請求、下載 HTML／CSS／JavaScript／圖片等資源後，再交給渲染引擎處理。
10. **快取**：把造訪過的資源暫存，減少重複請求、加快載入。
11. **非同步請求與 AJAX**：在不重整整頁的情況下向後端取資料、更新部分畫面，提升體驗。

**重點**：瀏覽器是 UI、渲染引擎、各解析器與 JavaScript 引擎協同工作的成果；了解它，有助於優化網頁效能與體驗。

### 2.6 使用 UML 作網站系統分析與設計

**UML（統一建模語言）** 是一種用圖形化符號描述系統結構、行為與互動的工具。它原本用於軟體工程，也同樣適用於網站開發。

#### 2.6.1 UML 對網頁開發的幫助

UML 提供一套標準符號，讓團隊能以圖形描述、設計與溝通系統，主要幫助包括：

- **需求分析**：把需求、功能與使用者互動視覺化，釐清目標。
- **系統架構與設計**：用類圖、組件圖描述組件與關係；用行為圖描述功能與流程。
- **介面設計**：用交互圖（序列圖、協作圖）呈現使用者的操作流程。
- **資料庫設計**：用類圖描述實體、屬性、關係與資料表的對應。
- **系統集成**：描述不同組件之間的訊息傳遞與資料交換。
- **文件生成**：自動產生設計、需求與架構等文件，方便溝通與參考。

#### 2.6.2 UML 圖表類型

UML 的圖表分為「結構圖（靜態）」與「行為圖（動態）」兩大類。

**結構圖**

- **類圖（Class Diagram）**：描述類別、物件、屬性與彼此的關係（最常用）。
- **物件圖（Object Diagram）**：表示類別的實例與其關係。
- **組件圖（Component Diagram）**：描述系統的組成部分，如模組、組件與介面。
- **部署圖（Deployment Diagram）**：顯示系統的實體部署，如伺服器與網路設備。

**行為圖**

- **用例圖（Use Case Diagram）**：表示功能需求與參與者之間的互動。
- **交互圖（Interaction Diagram）**：含序列圖與通信圖，描述物件之間的互動。
- **狀態機圖（State Machine Diagram）**：表示物件狀態與狀態轉換。
- **活動圖（Activity Diagram）**：描述業務流程、操作與工作流。
