第一部分｜環境建置：從下載到 Flow Web UI

這一階段的目標只有一個：在自己電腦上跑起 H2O 的網頁介面（Flow）

1.0 封面

標題：H2O AutoML。整份課程就是一條「從安裝到畫出走勢圖」的連續操作線。

1.1 造訪 H2O.ai 官網

操作：打開瀏覽器進入 H2O.ai 官網（截圖停在 H2O AutoML 產品頁）。

頁面上要認識的三件事：

位置 內容
主視覺 H2O AutoML｜副標 Scalable AutoML in H2O-3 Open Source｜黃色按鈕 Get Started
分頁列 Overview｜Goals｜Aspects｜Web GUI｜Resources
官網導覽列 SOLUTIONS｜PLATFORM｜ABOUT｜RESOURCES｜AI 100｜REQUEST LIVE DEMO｜SIGN IN

📌 官網對 AutoML 的定義（Overview 原文）： 「AutoML or Automatic Machine Learning is the process of automating algorithm selection, feature generation, hyperparameter tuning, iterative modeling, and model assessment. AutoML makes it easy to train and evaluate machine learning models. Automating repetitive tasks allows people to focus on the data and the business problems they are trying to solve.」

翻成白話：AutoML 把「挑演算法、生特徵、調超參數、反覆建模、評估模型」這五件苦工自動化，讓人專心在資料與商業問題上。這段話正好對應課程單元一講的「傳統 ML 三大痛點」。

💡 分頁列裡的 Web GUI 就是在預告本堂課的主角 —— 等一下要用的 Flow 網頁介面。

1.2 一路點到「Download H2O」

三步點擊，課程一次只做一件事：

  1. 向下捲動，點擊 “Start Using H2O AutoML”
  2. 點擊 “latest stable release page”（最新穩定版頁面）
  3. 點擊 “Download H2O”

💡 這三步的截圖是同一頁往下捲的連續動作，箭頭就是課程用來標示「點哪裡」的指示。

1.3 啟動 H2O 伺服器

下載頁上寫著「Get started with H2O in 3 easy steps」，課程把第 2 步的指令區塊稱為 prompt，做法是整段複製後貼到終端機：

cd ~/Downloads
unzip h2o-3.46.0.11.zip
cd h2o-3.46.0.11
java -jar h2o.jar
步驟 指令 作用
1 cd ~/Downloads 進入下載資料夾
2 unzip h2o-3.46.0.11.zip 解壓縮（本課程示範版本 3.46.0.11）
3 cd h2o-3.46.0.11 進入解壓後的資料夾
4 java -jar h2o.jar 啟動 H2O 伺服器（這行會一直佔用終端機）

第 3 步：Point your browser to http://localhost:54321。

下載頁另外兩個要注意的資訊：

  • 版本標示：Version 3.46.0.11
  • 安全性提醒：「By default, this setup is open. If you want to secure your installation, follow the Security Guidelines.」→ 預設是開放狀態，要對外提供服務前必須先做安全設定。

📖 補充說明（Windows 版指令）：本課程的指令是 macOS/Linux 語法。Windows PowerShell 的對應做法是： powershell cd $env:USERPROFILE\Downloads Expand-Archive .\h2o-3.46.0.11.zip -DestinationPath . cd h2o-3.46.0.11 java -jar h2o.jar 解壓後的資料夾裡可以看到 h2o.jar，以及 python/、R/、bindings/ 三個子資料夾（分別是 Python 套件、R 套件與 Java bindings）。

1.4 ⚠️ 最容易卡住的一步：Java 版本

症狀：指令都貼對了，但終端機卻印出錯誤訊息：

Only Java versions 8-17 are supported, system version is 23.0.1

（截圖同時顯示 unzip 的過程：h2o.jar、bindings/java/h2o-bindings-3.46.0.zip、python/h2o_client-3.46.0.11-py2.py3-none-any.whl、R/h2o_3.46.0.11.tar.gz 等都被正常解出 —— 檔案沒問題，問題出在 Java 版本。）

課程給的三個重點：

# 重點 說明
1 它僅支援 Java 8 至 17 版本 若你的 Java 是 23，請把 java -jar -Dsys.ai.h2o.debug.allowJavaVersions=23 h2o.jar 貼到終端機
2 請勿關閉終端機窗口，只需將其最小化即可 關掉＝伺服器被殺掉
3 終端機必須保持開啟狀態 因為它正在運行支撐 WebUI 的後台伺服器

繞道指令（Java 23 專用）：

java -jar -Dsys.ai.h2o.debug.allowJavaVersions=23 h2o.jar

⚠️ 這個參數只是「允許」啟動，不是「支援」：-Dsys.ai.h2o.debug.allowJavaVersions=23 是開發者除錯用的開關，屬於強制略過版本檢查。課堂示範可行，但正式環境請乖乖安裝 Java 8–17，避免遇到罕見的相容性錯誤。 🔍 檢查自己電腦的 Java 版本：java -version。

1.5 開啟 Flow Web UI

操作：返回網站（下載頁），點擊 “http://localhost:54321”，就會開啟 H2O 的網頁介面 H2O Flow。

💡 localhost:54321 是什麼？ localhost 代表「你自己的電腦」，54321 是 H2O 伺服器預設的埠號（port）。也就是說 —— 模型不是在雲端跑，是在你自己的電腦上跑，資料不會離開本機，這也是開源工具相對雲端平台（如 Azure ML）最大的差別。

第二部分｜資料匯入與解析

目標：把 CSV 匯入 H2O，並轉成 H2O 原生的資料框 .hex

2.0 先認識 H2O Flow 介面（這些畫面共同的元素）

位置 內容 說明
左上 H₂O FLOW 產品名稱
頂部選單 Flow ▾｜Cell ▾｜Data ▾｜Model ▾｜Score ▾｜Admin ▾｜Help ▾ 全部操作都從這裡開始
工具列 新增 Flow、開啟、儲存、＋（新增 cell）、↑↓、剪下／複製／貼上、刪除、▶（執行）、▶▶（全部執行）、？ 操作「cell」的按鈕
主工作區 一條一條的 cell（左側有 CS 標籤） 輸入指令 → 執行 → 下方直接顯示結果
右側面板 OUTLINE｜FLOWS｜CLIPS｜HELP 大綱、已存 Flow、片段、官方說明
底部狀態列 Ready、Connections: 0、H₂O 版本 確認伺服器活著

💡 Flow 的運作模式：Flow 其實是一個「筆記本式的網頁介面」（像 Jupyter，但每格是 H2O 指令）。你每按一次選單，它就在 cell 裡幫你寫好指令並執行，所以左側常會看到 importFiles、parseFiles、getModel 這種指令 —— 看懂這些指令，就等於看懂 H2O 的 API。

2.1 點選 “Data” → “Import Files”

操作：點選 “Data”，然後選擇 “Import Files”。

2.2 把檔案路徑貼到 “Search”

操作：將 monthly_training_set.csv 的檔案路徑貼到 “Search”。

⚠️ 貼的是檔案在電腦上的完整路徑，不是檔名。課程示範的路徑是 /Users/isaacchen/Redix/monthly_training_set.csv（macOS）。

2.3 點選放大鏡與 “＋”

操作：點選放大鏡圖示和 “＋”。

欄位 截圖顯示的內容
Search /Users/isaacchen/Redix/monthly_training_set.csv
Search Results Found 1 file: Add all
搜尋結果清單 ＋ /Users/isaacchen/Redix/monthly_training_set.csv
Selected Files (No files selected) ← 還沒選，所以要按 ＋
Actions Import（灰階＝尚不可按）

💡 為什麼要按 ＋？ 放大鏡只是「搜尋」，按 ＋ 才是「把這個檔案加入待匯入清單」；加入後 Selected Files 才有內容，Import 按鈕才會亮起。

2.4 點選 “Import”

操作：點選 “Import” → 檔案被讀進 H2O 叢集。

2.5 點選 “Parse these files”

操作：點選 “Parse these files”。

💡 Import 與 Parse 的差別（很重要）： - Import＝把檔案搬進 H2O 的記憶體（此時還只是一包原始位元組）。 - Parse＝解讀格式：切欄、判斷型別、處理表頭，最後產生 .hex 資料框。 就像「把 Excel 檔複製到電腦」與「用 Excel 打開它」是兩件事。

2.6 把 “Ticker” 設為 “Enum”，然後點選 “Parse”

操作：將 “Ticker” 設定為 “Enum”，然後點選 “Parse”。

名詞 白話解釋 為什麼要設 Enum
Numeric（數值） 可以加減乘除的數字 股票代碼是「代號」，不是「數量」
Enum（列舉／類別） 有限的幾個類別 941、1515、3320 只是三檔股票的名字，設成 Enum 才不會被模型當成「大小關係」

⚠️ 這是本堂課最容易做錯的一步：如果 Ticker 留在 Numeric，模型會以為「3320 比 941 大 3 倍多」，學出完全沒有意義的關係。類別欄位一定要設 Enum（等同於其他工具的 one-hot / categorical）。

2.7 欄位解釋

課程用一整頁解釋這 5 個欄位：

欄位 中文 角色
Date 交易日期 時間欄位（等一下會被 ignored）
Close 當月收盤價 預測目標（response）
Close_Lag1 上月收盤價 特徵（延遲 1 期的收盤價）
Ticker 股票代碼 類別特徵（Enum）
Month 月份 特徵（1–12，用來學季節性）

📌 一句話看懂這份資料的建模設計：用「上個月的收盤價 + 股票代號 + 月份」去預測「這個月的收盤價」。這是典型的時間序列 → 監督式學習轉換（把時間軸上的「上一期」變成一個特徵欄位）。

2.8 “Parse” 結果與完整參數

執行後 Flow 會產生一個 parseFiles cell，內容就是這次解析的完整設定：

parseFiles
  source_frames: ["nfs:///Users/isaacchen/Redix/monthly_training_set.csv"]
  destination_frame: "monthly_training_set.hex"
  parse_type: "CSV"
  separator: 44
  number_columns: 5
  single_quotes: false
  column_names: ["Date","Close","Close_Lag1","Ticker","Month"]
  column_types: ["Time","Numeric","Numeric","Enum","Numeric"]
  delete_on_done: true
  check_header: 1
  chunk_size: 4194304
  escapechar: undefined

下方的 Job 卡片回報執行狀況：

欄位 值
Run Time 00:00:00.45
Type Frame
Key monthly_training_set.hex ← 這就是資料框的名字
Description Parse
Status DONE
Progress 100%
Actions View（可預覽資料）

💡 要記住的 3 個細節： 1. separator: 44 → 44 是逗號的 ASCII 碼，也就是 CSV。 2. column_types 的第 4 個是 Enum → 確認剛剛把 Ticker 設對了。 3. destination_frame: "monthly_training_set.hex" → 等一下 Run AutoML 要填的就是這個名字。

第三部分｜Run AutoML：讓 H2O 自己訓練與挑模型

目標：用一個選單 + 幾個參數，讓 H2O 自動訓練與評比大量模型

3.1 點選 “Model” → “Run AutoML”

操作：點選 “Model”，然後選擇 “Run AutoML”。

3.2 設定訓練資料與預測目標

training_frame:   monthly_training_set.hex
response_column:  Close
參數 填什麼 意義
training_frame monthly_training_set.hex 用哪個資料框訓練（就是剛剛 Parse 出來的那個）
response_column Close 要預測哪一欄 → 當月收盤價

💡 這兩個參數決定了「用什麼資料、預測什麼」。填完之後，其餘欄位 H2O 會自動當成特徵 —— 所以下一步要手動排除不需要的欄位。

3.3 排除日期欄

ignored_columns:  Date

⚠️ 為什麼一定要忽略 Date？ 日期是「時間戳」，直接餵給模型會產生兩種問題：① 模型可能死記「某年某月」的數值，學到無法外推的規則；② 對未來（2024–2027）而言，那些日期根本不存在。時間資訊要用 Month（季節性）與 Close_Lag1（延遲值）來表達，而不是把原始日期丟進去。

3.4 時間預算與交叉驗證設定

max_runtime_secs: 300
取消勾選：keep_cross_validation_predictions、keep_cross_validation_models

課程截圖完整列出 Run AutoML 的參數表，每一列右邊都有官方說明：

4.5 撰寫預測程式：stock_prediction.py

操作：輸入模型存放路徑至 model_path（課程箭頭指的就是程式第 6 行）。

這頁截圖裡是完整的程式碼（Cursor / VSCode 的 stock_prediction.py），逐字照抄如下：

import h2o
import pandas as pd

h2o.init()
# 填入你在 WebUI 得到的最新最佳模型 ID
model_path = ""
model = h2o.load_model(model_path)

train_df = pd.read_csv("monthly_training_set.csv")
predict_df = pd.read_csv("monthly_prediction_set.csv")

tickers = ["0941", "3320", "1515"]
final_results = []

for t in tickers:
    # 抓取 2023 年 12 月底的最後一個真實收盤價作為發動引擎的「種子價格」
    last_close = train_df[train_df['Ticker'] == int(t)].sort_values('Date').iloc[-1]['Close']

    stock_predict = predict_df[predict_df['Ticker'] == int(t)].sort_values('Date').copy()
    current_lag = last_close

    for idx, row in stock_predict.iterrows():
        stock_predict.at[idx, 'Close_Lag1'] = current_lag

        # 預測下個月
        h2o_row = h2o.H2OFrame(pd.DataFrame([stock_predict.loc[idx]]))
        pred = model.predict(h2o_row)
        pred_val = pred[0, 0]

        # 把這月的預測值儲存，並變成下個月的特徵
        stock_predict.at[idx, 'predict_Close'] = pred_val
        current_lag = pred_val

    final_results.append(stock_predict)

# 將資料表合流並下載成實體檔案
final_df = pd.concat(final_results, axis=0)
output_filename = "trend_2024_2027.csv"
final_df.to_csv(output_filename, index=False)

print(f"預測成功！檔案已順利生成並儲存至: {output_filename}")

逐段解說：

行 程式碼 在做什麼
1–2 import h2o / import pandas as pd 載入 H2O 與資料處理套件
4 h2o.init() 啟動／連線到 H2O 伺服器（若本機沒有，會自動開一個）
5–7 model_path = "" → h2o.load_model(model_path) 把 Flow 匯出的模型載入記憶體 ← 這裡要填 4.4 匯出的路徑
9–10 pd.read_csv(...) 讀入訓練資料與預測骨架
12 tickers = ["0941", "3320", "1515"] 三檔港股（字串，下面再轉 int 對齊 CSV 裡的數值）
16 last_close = ...iloc[-1]['Close'] 抓最後一個真實收盤價當「種子價格」（2023 年 12 月底）
18–19 stock_predict = ...copy() / current_lag = last_close 取出該股票要預測的月份，並把種子放進 current_lag
21–23 for idx, row in ... / stock_predict.at[idx,'Close_Lag1'] = current_lag 把「上個月的值」寫進特徵欄（第一輪＝真實值，之後＝預測值）
25–28 h2o.H2OFrame(...) → model.predict(...) → pred[0, 0] 轉成 H2O 格式 → 呼叫模型預測 → 取出數值
30–32 stock_predict.at[idx,'predict_Close'] = pred_val / current_lag = pred_val 存下預測值，並把它當成下個月的輸入
34 final_results.append(stock_predict) 三檔股票的結果先各自收集
37–39 pd.concat(...) / to_csv(...) 合併成一份表，輸出 trend_2024_2027.csv

📌 這段程式的靈魂在「遞迴預測」：預測完 2024 年 1 月 → 把預測值當成 2 月的 Close_Lag1 → 再預測 2 月 → …… 一路推到 2027 年。這叫 recursive forecasting，優點是不需要未來的真實資料就能一路外推，缺點是誤差會累積（模型把 1 月的誤差帶進 2 月，再帶進 3 月）。

⚠️ 注意第 16 行的註解寫「2023 年 12 月底」，而 CSV 的 Ticker 是整數 —— 所以程式用 int(t) 來比對，"0941" → 941。
