CODING AGENT HARNESS · 八章專題

從零打造一個 coding agent

六個零件、一個迴圈，與 Ralph 迴圈真正的位置。

做一個 coding agent，難的從來不是模型，而是context 管理、工具權限、驗證迴路與失敗恢復。把這四件事做對，你就已經做出 Claude Code 的核心骨架——模型只是隨時可以換掉的零件。

起點：Geoffrey Huntley〈Replaced〉引發的爭論 × Tobi Lütke 的 Shopify 內部備忘錄｜對照：Cline CLI、Pi｜附本機八次實測

TL;DR — 五句話看完
  • agent = 模型 + harness。模型提供智能，harness（外殼）負責把智能變成真實世界裡的工作。這份專題講的是 harness。
  • 任何 coding agent 拆開都是六個零件：模型、工具、迴圈、Context 管理器、護欄、驗證器。前五個是內層 agent，第六個加上「規格檔 + 每輪單一任務」就是外層 Ralph 迴圈。
  • 第 6 個零件不是選配——「完成」的定義必須是可驗證的（測試綠燈、型別通過、diff 符合預期），而不是模型說「我做完了」。
  • harness 完整 ≠ 強 agent。Cline CLI 把六個零件做到生產級，Pi 把核心拆到只剩四個原子工具；兩者證明了同一件事：harness 可以下載，判斷力不行。
  • 本機實測補上最後一塊：同一個 harness、同一個任務，8B 模型的輸出是 27B 的 12.3 倍；而 prompt 快取狀態的影響（冷 29.5s／暖 10.1s）比模型參數還大。

這份專題的立場

「資深工程師要能重建 Claude Code」適合當成練習目標，不適合當成資格判定。真正會被淘汰的不是「沒有自己寫 Claude Code」的人，而是仍然只用 AI 複製貼上、無法設計驗證、也不願承擔工程責任的人。
