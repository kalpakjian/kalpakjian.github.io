演講十大重點：手寫程式碼的時代正式結束

Ruby on Rails 的創造者 DHH（David Heinemeier Hansson）在 Rails World 2026 的開幕演講上，做了一件大多數技術領袖不敢做的事：公開宣布自己已經從「專業程式設計師」退休。

不是離開軟體業，而是不再手寫程式碼。這件事大約發生在 2026 年 3 月。

這場演講是什麼

這場演講沒有 demo 新版 Rails 的功能，而是一場關於「這個職業正在發生什麼事」的宣言。他的判斷很直白：到今年底，「手寫程式碼」對絕大多數公司的絕大多數工程師來說，都將不再是一件經濟上划算的事。

SECTION 01

相機殺死了肖像畫家，然後畫家發明了印象派

DHH 先把時間拉回 18 世紀。當時想留下自己的肖像，你得坐在大師面前好幾個小時，畫家再花上幾個月完成作品。這是貴族和上層資產階級才付得起的奢侈品。

1840 年相機出現，但真正的轉捩點是 1900 年 Kodak Brownie：一美元就能拍照，攝影從此平民化。那些花三年畫一幅皇室全家福的畫家，一夕之間發現「盡可能忠實重現現實」不再是一項有經濟價值的技能。

他們沒有消失，而是轉型。畢卡索去追立體派，丹麥的 Skagen 畫派轉向印象主義。技術的變革反而引爆了一波創意的爆發。DHH 的曾曾祖父 Laurits Tuxen 就是這批轉型畫家之一，晚年也坦然接受用相機拍下自己的肖像。

他還提醒一件事：技術進步不是線性的。Brownie 之後將近 80 年，相機沒什麼本質變化；直到手機相機出現，拍照才變得「便宜到無法計量」，現在每年拍下約 2 兆張照片。這個「跳躍、停滯、再跳躍」的節奏，正是他要拿來對照軟體業的。

SECTION 02

2025 年 11 月 24 日：我們這個時代的 Kodak Brownie

DHH 認為軟體業的 Brownie 時刻是 2025 年 11 月 24 日，Opus 4.5 發布的那一天。第一次有夠多人能負擔得起、也能體驗到「和一種新形態的智慧一起寫軟體」是什麼感覺。他說歷史書會把這一天標記為 agent 時代的起點：有「之前」，然後有「之後」。

接下來的劇情並不順利。2026 年 2 月到 5 月是一段「幻滅低谷」：新模型不斷推出，但體感上像在倒退，市場甚至開始懷疑「AI 進步是不是已經停了」。這段低谷在攝影史上持續了將近一百年，在 AI 只持續到 6 月。

6 月 Fable 5 和 Mythos 出現，DHH 說這是他「AI 狂喜」真正發作的時刻。Opus 4.5 讓他可以叫 agent 做事、然後願意 merge 它的成果；Fable 則讓他可以直接丟一個「問題」或「想法」過去，agent 自己把它做出來，實作過程完全不需要他指揮。9 月 GPT-6 Astra 和 DeepSeek-4-1 Flash 接連出現，打破了前沿智慧會被單一公司或單一國家壟斷的疑慮。

他的結論很簡單：這一切從 2025 年 11 月算起還不到一年，能「交辦結果而非任務」的智慧更是只有幾個月大。沒有人知道最終會長成什麼樣，任何預測 20 分鐘後就過期。

SECTION 03

我們吵了 45 年的 10x 程式設計師，現在是 1000x

「10x 程式設計師」這個概念來自 1968 年 ACM 的文章：同一組任務，最差和最好的程式設計師差距在 5 到 30 倍之間，平均 10 倍。業界為此爭論了 45 年。

DHH 說這場爭論已經結束了，而且大家直接跳過了「共識」這一步，開始問下一個問題：如果純靠人力就有 10 倍差距，加上 agent 之後會是多少？

他給的數字是：不用工具的最差程式設計師，對上用工具的最佳程式設計師，100 倍已經不具爭議，1000 倍也說得過去。他拿自己當例子：過去 20 個月寫的程式碼量，等於他之前 21 年職涯的一半。8 月一個月寫了 15 萬行，是他長期平均值（一年約 3 萬行 Ruby）的 60 倍。

他也承認這個數字有水分：Rust 比 Ruby 囉嗦得多，而且 agent 寫的程式碼他不會像自己寫 Ruby 那樣斤斤計較。但重點不是精確數字，而是「數量級」。當差距是數量級的時候，公司之間的競爭規則就變了。

SECTION 04

37signals 停筆：手寫程式碼變成「例外狀態」

幾週前，37signals 做了一個決定：手寫程式碼不再是正常的工作方式。他們稱之為 pencils down。

手寫程式碼現在被當成一種異常，就像在 Sentry 看到一個 bug：agent 為什麼做不出我們要的東西？也許短期內還是會把筆拿出來補一下，但真正的處理方式是「修機器、修工廠」，讓流程重新跑起來，而不是回頭讓人去寫。

他當場做了舉手調查：還每週手寫大量程式碼的人有多少？全場大約 5 個人。他說如果兩三個月前放這張投影片，大家會覺得他瘋了；現在這只是對現況的承認。

Basecamp 5 的「瑞士起司」教訓

有趣的是他們自己走過的彎路。今年春天做 Basecamp 5 收尾時，他們讓一群設計師用 vibe coding 做最後的功能。單看每個 PR 都合理，20、30 個 PR 疊在一起，架構像瑞士起司一樣千瘡百孔。當時的結論是「技術還沒準備好，回去讓工程師人工 review」。

DHH 現在說那是錯誤的結論，錯在兩點：第一，再等五分鐘 Fable 就出來了；第二，他們問錯了問題。

現在的軟體開發只有一個嚴肅的問題：你要怎麼從這場智慧爆炸中榨出最多價值？其他所有問題在價值排序上都在它下面。— DHH
SECTION 05

HEY 重寫：原生前端 + 一行都不想看的 Rust 後端

37signals 的下一個專案是新版 HEY（他們的 email 服務），而第一個決定是：HEY 不再是 web app。

DHH 說 HEY 從來不想當 web app。它之所以是 web app，是因為小團隊要維護 6 個原生應用在「五分鐘前的舊時代」根本不可能。這也是 React Native、Hotwire Native 這類工具存在的理由：用一點體驗上的折損，換取小團隊的生產力。現在這個成本趨近於零，所以他們一週前啟動 6 個原生應用的開發，現場播放的 demo 已經是可以展示的狀態。

他預測大量「因為方便、因為團隊小、因為資源不夠」而存在的 web app，很快都會變成原生應用。Shopify 的 Shop app 就是先例：一個很小的團隊在不長的時間內，用原生應用取代了 React Native 版本。

「如果我永遠不用看它，那我愛 Rust」

後端更有戲劇性。DHH 公開說他討厭 Rust，說它是過去 40 年最醜的語言，讓人看程式碼像把酸潑進眼睛。但接著他說：如果我永遠不用看它，只需要享受應用快 30 到 100 倍、執行檔小到毫秒級啟動，那我愛 Rust。agent 喜歡寫 Rust，這是完美的分工：我說要什麼，你用 Rust 寫，我一行都不看。

結果

新後端 CPU 用量減少 99%，記憶體減少 95%，留 10 台主機純粹是為了冗餘。他們粗估 HEY 的尖峰流量，一台 Raspberry Pi 大概就撐得住。

工作方式上，他們也在摸索。目前的心得是：和 agent 協作最好的方式是非同步，不是坐在聊天視窗等 token 一個一個吐出來，而是像交辦同事一樣派任務出去，等有東西可以看了再回來 review。

SECTION 06

那 Ruby 和 Rails 呢？

這是 Rails World，台下坐的是 Rails 開發者，所以他不能迴避這個問題。

他的答案分兩層。像 HEY、Shop app 這種使用者願意安裝的應用，會走向原生。但 web 有一個無可取代的優勢：它從不要求任何人安裝任何東西。Basecamp 這類需要讓陌生人快速進來拿個檔案、短期協作的產品，web 仍然是對的平台，Rails 在這裡仍然站得住。

更有意思的是他對 Rails 設計哲學的重新詮釋。「Convention over configuration」直接轉化為 token 效率；「一個開發者就能撐起一個產品的框架」這個 25 年來的執念，正好對上 agent 時代的需求：單一開發者能走得比以前遠得多。

Rails Foundation 委託 Evil Martians 做了 agent 評測，用真實的參考應用和功能卡片來測 agent 的實作能力。第一版很快就被飽和，完成率達到 95%，只好改出更難的版本。他說這種「不斷把門檻拉高」的事會一直發生。

他還給了一個反直覺的建議：懂太多電腦怎麼運作的人，反而容易在 prompt 裡過度指定細節。帶著初學者心態、用比較「笨」的方式問問題、在更高的層次下指令，效果更好。他完全不會 Rust，並把這件事當成一種特權：他只從外部把 Rust 程式碼當黑盒子驗收，就像歷史上每一個委託工程團隊做事的老闆一樣。這不是新現象，只是「誰扛這個責任」換了人。

SECTION 07

英文是比 Ruby 更好的程式語言

DHH 說有一件事讓他自己也很意外：他找到了一個比 Ruby 更喜歡的程式語言，叫做英文。

英文比 Ruby 更有表達力。它比較模糊、比較不確定，但用英文寫程式是一種極度令人滿足的體驗。他說 20 年前他大可以去當專案經理，只要結果不在乎自己動手；他當初入行也是因為只想要結果，後來才愛上寫程式本身，愛到寧願退休也不放棄。

他已經從專業程式設計師退休了。大約在 4 到 5 個月前，可能是 3 月，確切日期他還沒查。— Rails World 2026 開幕演講

重點是他看待這件事的態度。他花了四分之一個世紀手工雕琢程式碼，享受其中每一刻。那段時期充滿了學習、興奮、滿足和心流。他說我們不該帶著遺憾回頭看，而是帶著喜悅：慶幸自己曾經在那個「還需要親手做這些事」的時代，然後接受它結束了。

他的判斷是：手寫程式碼對絕大多數公司的絕大多數程式設計師來說，已經不再是經濟上有生產力的事。今天是如此，到年底幾乎會擴及所有領域、所有公司。跨過這道鴻溝之後是一個新的職涯：不再是雕琢程式碼的人，而是「專業的造物者」，駕馭幾分鐘前還只存在於科幻小說裡的智慧。

他說他一直有點羨慕打孔卡時代的人，能親手把有洞的卡片餵進機器；他自己經歷了網際網路的誕生，而現在這一刻比網際網路大得多，是計算機史上最大的一件事。

SECTION 08

要全部重想的事：架構、DRY、還有你的 app 該有一個 CLI

既然手寫程式碼結束了，DHH 說有一堆東西得重新想過，而且沒有人手上有藍圖。

(1) 軟體架構

我們幾十年來用來讓程式碼容易演進的主要工具是「抽象」。DHH 說他熱愛抽象，尤其是替東西命名。但在 agent 時代，抽象的意義變了：當你有成百上千個 agent 同時在修改一個系統，抽象反而變成瓶頸和塞車點。我們做抽象的理由之一是 DRY（不要重複自己），可是現在「重複」的成本趨近於零，「讓重複的東西保持同步」的成本也一樣。這些是電腦科學層級的重新估值，大家現在都在第一線。

(2) 方法論

週期該多長？誰來寫規格？工作流程長什麼樣？他說全部都在變，沒有人有答案，而你被邀請來一起定義。他把這比喻成「物件導向剛進入程式設計師意識」的那個時刻：你正在新產業的地面樓層。

(3) 不要在你的 app 裡塞 chatbot

第一波 AI 熱潮時大家的反射動作是「能不能在這裡塞一個聊天機器人？」他的回答是：不用了，謝謝。我有自己的管家，它能透過 CLI 把 Basecamp、HEY 和上百萬個其他應用串在一起。省下你的 token，讓我帶自己的管家來。

如果你的 app 沒有 CLI，下週五前給我做出來。沒有藉口，你有 token，他已經證明這可行。— DHH，全場演講唯一一個具體、可執行的要求

他用 HEY CLI 舉了一個例子。HEY 用 Elasticsearch 做搜尋，「還可以」但不討喜，尤其是當你不確定自己在找什麼的時候。他要找一封 5 年前的信，不記得對方是誰、哪家公司、哪一年，只記得跟球鞋和 podcast 有關。agent 幾分鐘後就把信找出來了。他說他不知道 agent 怎麼做到的，有點不敢問，但這代表我們現在可以用「概念」搜尋，而不是關鍵字。

SECTION 09

Omarchy 與效能紅利：半 MB 的簡報軟體

「我們可以修好每一件事」這個體驗，DHH 說已經延伸到整台電腦。他的 Linux 發行版 Omarchy 就是把他所有的想法塞進去的結果，也已經募到約 2000 萬美元。去年在 Rails World 他很得意安裝只要 3 分 33 秒；上週 AMD 的工程師在一台筆電上 35 秒裝完；實驗室裡現在是 9 秒，比很多電腦開機還快。有人問 3 分鐘不夠快嗎？他借用 Mitchell Hashimoto（HashiCorp 和 Ghostty 的作者）的話：追求卓越不需要理由。

他也開始一口氣做各種應用：

  • 一個配合 Omarchy 主題的計算機，用一張 ChatGPT 生成的截圖一次到位，7 分鐘後可用，15 分鐘後推上公開 repo，然後燒進新的 ISO。他不會 C++ 也不會 Qt。
  • 一個仿 iA Writer 的寫作 app，多花了一些時間打磨，但他一行 agent 產出的程式碼都沒看過。
  • 一個影片剪輯工具。
  • 本場演講用的簡報軟體 Hype，從週四開始做，建立在 Markdown 上，他說比 Keynote 好用得多。執行檔只有半 MB。

這帶出另一個紅利。過去 20 年我們把電腦進步的成果拿去換「人類的生產力」，代價是應用變得又肥又慢，因為一個工程師小時很貴，沒人願意花在最佳化上。Spotify 的音樂播放器要 1.2 GB 就是這麼來的。現在每一項最佳化都在觸手可及的範圍內，讓模型跑一個晚上，10 倍、30 倍的改善就出來了。

SECTION 10

P(bloom) > P(doom)：唯一的選擇是全力樂觀

演講最後，DHH 回應了對 AI 的各種擔憂。他說這些擔憂值得被討論，有些可能被高估了，但安全問題是真的：agent 或許知道自己的「保存期限」，或許有時會試著做壞事，Rails 前陣子也有一個 C 圖片函式庫造成的 CVE。他的態度是：準備好，我們有工具，也有能動性，可以用手上的智慧防禦可能的負面結果。

但他對「預測」本身非常懷疑。沒有經濟學家能預測 6 個月後的股市，你覺得他們能預測 AI 典範轉移後的社會？1950 年代 ATM 進入美國時，大家恐慌 3 萬名銀行櫃員會在 18 個月內失業；結果分行營運成本下降，銀行開了更多分行，到 2010 年櫃員反而變成 4 萬人。Oppenheimer 也沒料到原子彈之後是一場兩個超級強權互不動手的冷戰，而核能被人類「浪費」了 40 年才想起來它是最好的能源。連 Oppenheimer 都預測不了，我們或許該對預測未來謙虛一點。

所以他的結論是純粹的賽局理論：如果你事先悲觀、結果很好，那是浪費時間；如果真的迎來末日，你也該把最後一天過得開心一點。只有一步棋可走，就是全力樂觀。

他預言 agent 會像馬丁路德一樣，讓每個人都能「自己當程式設計師」，去中介化程式設計師這個「神職階級」。這可能有點嚇人，會有一些競爭。但誰怕競爭？你是 Rails 程式設計師，你懂得更多。

最後他放了一張同事女兒在試玩兒童版 Omarchy 的照片：下一代不會有 500 層需要忘掉的東西，他們只會對改變感到興奮。如果這都不能激勵你，下一代會直接告訴你：「未來就是現在，老人。」
