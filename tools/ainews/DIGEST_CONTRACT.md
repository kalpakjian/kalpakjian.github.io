# AINews 導讀寫作規格（DIGEST CONTRACT）

> 目的：讓**機器人寫的稿**跟**我手寫的稿**長得一樣，而且**不可能寫出我沒讀過的東西**。
>
> 這份契約跟 `tools/notes-qa/NOTE_STYLE_CONTRACT.md` **不同用途**：那份管 PDF 筆記（`原稿／教材／頁碼`），
> 這分管**新聞導讀**。兩者唯一共通的是：**md 是唯一來源、產出後要過閘門**。

依據：站上已發布的兩篇實例
`ainews-weight-space-programming-zh.md`（18.9 KB）、`ainews-anthropic-ipo-whither-now-zh.md`（31.4 KB）。

---

## 0. 一條鐵律

> **每一個數字、每一個專有名詞，都必須能在 `extract.json` 裡找到出處。**
> 找不到出處的，不准寫進「事實」段落；若真的是我的推論，必須放進標了「我的判讀」的章節。

這條比任何風格規則都重要。前兩篇之所以可信，是因為每個數字都能回到原文。

---

## 1. 骨架（必須完全一致）

```
frontmatter
導言 blockquote（3–4 段，標明哪些章節是原文整理、哪些是判讀）
## 一句話總結              ← 必須有，且必須是「一句」
## 1. <頭條>               ← 當期最大的一條，含數字表或 SVG
## 2. 我的判讀：<一句主張>   ← 原則是「新聞版 vs 技術版」的落差
## 3. 當期其他重點（速覽）   ← 表格為主
## 4. <深入章節>            ← 評測／安全／技術細節，可有多節
## 5. 我的總結
### 5.1 三句話            ← 固定三條 blockquote
### 5.2 追蹤清單           ← checkbox 列表
### 5.3 原文連結           ← 郵件主旨、網頁版、站內延伸
<small>出處與生成方式聲明</small>
```

**為什麼要固定**：讀者點進來就知道去哪找結論；而且機器人只要偏離骨架，`digest_lint.py` 立刻會抓到。

## 2. 章節配額

| 章節 | 字數 | 圖 | 表 |
|---|---|---|---|
| 一句話總結 | 60–200 | — | — |
| 1. 頭條 | 800–2,500 | 1 張 SVG | 1–2 |
| 2. 我的判讀 | 800–2,000 | 0–2 張 SVG | 0–2 |
| 3. 速覽 | 1,000–3,000 | 0–1 | 2–4 |
| 4. 深入 | 1,500–4,000 | 1–2 | 1–3 |
| 5. 總結 | 300–700 | — | — |

**全文**：**4,000–12,000 字**、**至少 2 張內嵌 SVG 圖**、**至少 5 張表**。

> 門檻是**照已發布的兩篇校準**的，不是憑空訂：權重那篇 2 圖 5 表、IPO 那篇 5 圖 6 表。
> 一開始我訂 3 圖 6 表，結果把自己認可的文章判成不合格——**閘門必須先通過黃金樣本，才有資格擋人**。

低於 4,000 字 → 這期不值得寫長文，走「短訊」模式或跳過（見 §6）。

## 3. 語氣規則

| 要 | 不要 |
|---|---|
| 主觀但有依據：「我認為方向對，但省掉的不是那一圈」 | 「毫無疑問」「必然」「徹底改變」 |
| 明確標示信心：「我持保留」「這條只有弱證據」 | 把 rumor 當事實陳述 |
| 對原文保留英文原句（引號內） | 全文中英夾雜卻不加引號 |
| 台灣正體用語（資料、程式、網路、最佳化） | 簡體用語（数据、程序、网络） |
| 明確區分「原文說」與「我判斷」 | 兩者混寫 |

**引號規則**：引用原文用 `> *"..."*`，緊接中文翻譯用 `>`，例如：

```markdown
> *"the world has now gone from 0 to 1 on this very new RSI capability"*
>
> （這條全新的 RSI 能力剛從 0 走到 1。）
```

---

## 4. 「我的判讀」章節怎麼寫

這是整篇的價值所在，也是最容易寫壞的地方。**必須有一個可反駁的主張**，格式：

1. **先給主張**（一句話，可被反駁）
2. **再給證據**（表格或對照，每格都來自原文）
3. **最後給邊界**（什麼情況下我這個判斷會錯）

反例（不要寫）：「這件事很重要，值得關注。」← 沒有主張，無法反駁。

正例（前兩篇用的）：
> 「84 寫成 80 的距離，比 1.5T 寫成 1T 更值得注意。」
> 因為營收是事實、估值是共識，事實差 20% 比共識差 33% 更難補。

## 5. SVG 圖規則（沿用站上實例）

只用**手繪 inline SVG**，不用點陣圖、不引用外部資源。

```html
<!-- FIG1 -->
<figure style="margin:24px 0;padding:14px 12px;overflow-x:auto;background:#0d1117;border:1px solid #222b36;border-radius:12px;text-align:center">
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 940 470" role="img" aria-label="...">
...（全部內容放在同一段，中間不要空行）
</svg>
<figcaption style="font-size:13.5px;color:#9aa7b4;margin-top:10px;line-height:1.65;text-align:left">圖 1：...</figcaption>
</figure>
<!-- /FIG1 -->
```

**血淚規則（這幾條都是實際踩過的）**：

1. ⛔ `<svg>` **內部不能有空行**，否則 Hexo 的 marked 會把它拆成 `段落會插入 <p>`，整個圖形會壞掉。
   （第 2 篇的圖 2 就是這樣壞過一次。）
2. ⛔ `##` 的正則不要用 `^##\s*`，會誤吃 `###`。
3. ✅ 配色固定：底色 `#0d1117`、卡片 `#161b22`、主強調 `#2dd4bf`、次強調 `#58a6ff`、
   警示 `#fbbf24`、負面 `#ff7b72`、文字 `#e6edf3` / `#8b949e`。
4. ✅ 字型固定 `'Segoe UI','Microsoft JhengHei','Noto Sans TC',sans-serif`。
5. ✅ 每張圖都要有 `<figcaption>圖 N：一句話說明它證明什麼</figcaption>`。

## 6. 該不該寫？——「短訊 vs 導讀」的分流

不是每一期都值得 8,000 字。用 `extract.json` 的 `stats` 判斷：

| 條件（全部成立才寫導讀） | 否則 |
|---|---|
| `quantities >= 40`（有足夠硬數字） | 短訊模式：1,500 字、1 張圖 |
| `chars >= 40,000`（內容夠厚） | 短訊模式 |
| `sections >= 4`（有真正的新聞分區） | 可能只是公告，跳過或短訊 |
| 標題不是 `Behind Latent Space` 類的活動宣傳 | 跳過（那是活動廣告） |

**降級為短訊時**：只寫「一句話總結 + 三個要點 + 原文連結」，不寫判讀章節。

---

## 7. 絕對不能做的事

| ⛔ | 為什麼 |
|---|---|
| 寫出原文沒有的數字 | 這是唯一會毀掉整站可信度的錯 |
| 把 `unconfirmed` / `rumor` / `reported` 寫成事實 | 前兩篇都特別標「未證實」 |
| 抄贊助商文案 | 抽取器已經刪掉了，但別從別處補回來 |
| 使用「本節」「原稿」「教材」等筆記用語 | 那是 PDF 筆記的詞彙 |
| 把活動廣告（`Behind Latent Space`）當新聞寫 | 那不是新聞 |
| 產出少於 3 張圖就發布 | 讀者體驗不一致 |

## 8. 產出後的閘門

```powershell
# 1) 結構與數字溯源（快，pre-build）
python tools/ainews/digest_lint.py --post source/_posts/<slug>.md --extract tools/ainews/out/<id>/extract.json

# 2) 粗體的「實際渲染」檢查（唯一可信；需要先 build）
npx hexo generate
python tools/ainews/check_bold_render.py --html public/2026/11/07/<slug>/index.html
```

檢查項目見 `digest_lint.py` 的 `CHECKS`。**任何 ERROR 都必須修掉才能發布**；
WARNING 只提示，不阻擋。

### 為什麼粗體要分兩個工具

我試過三次用正則從**原始碼**判斷粗體會不會失效，三次都錯：其中一版對一篇
渲染出 130 個 `<strong>` 的文章報了 102 個錯。原因是我在猜 CommonMark 對中文的 flanking 規則。

後來改成量測**渲染結果**才找到真相：失效的只有「結尾 `**` 後面直接接中文或全形標點」這一種，
其餘（`**「…」**`、`**+49.8 分**（SE 1.5）`、表格裡的粗體）全部正常。

> **教訓：能實測就不要推理。** 所以 `digest_lint` 的 S020 只給 WARNING 並指向
> `check_bold_render.py`——那支才是判準。

---

## 9. 一句話原則

> **機器負責「不漏、不編、格式對」，人負責「這期值不值得寫、我的判斷是什麼」。**
>
> 所以階段 3 產出的是**草稿 + 一份「該檢查什麼」的清單**，不是成品。
